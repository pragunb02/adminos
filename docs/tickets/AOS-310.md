## Description
- The web app had **0 tests**. This adds a unit and component test harness and tests every helper, component and page:
  - each state: loading, empty, error + retry, data;
  - each action: success and failure;
  - each branch.
- `npm test` fails if coverage drops below **90% of lines** or **85% of branches** (Pragun, 2026-10-16).

## Why
- Pragun asked for tests "covering every type of scenario, every branch, and every user experience on a particular screen".
- The console screens (AOS-303…309) are built on this harness.

## Scope
- **In:**
  - Vitest 5 + jsdom + React Testing Library + user-event + jest-dom;
  - MSW 3 for network mocks (the same handlers are reused by Playwright, AOS-311);
  - v8 coverage with thresholds;
  - tests for `lib/*`, `components/*` and every page.
- **Out:** browser end-to-end and navigation history (AOS-311); API coverage (AOS-312).

## Acceptance criteria
- [x] `npm test` runs every test in CI style (no watch); `npm run test:coverage` enforces 90% lines and 85% branches over `src/**`.
- [x] Every page: loading, empty, error + retry, data; every action's success and failure path.
- [x] `lib/api.ts`: envelope parsing, non-JSON bodies, 401 → one refresh → retry, refresh failure → /login, logout.
- [x] `lib/query.ts`: unwrap, `ApiError`, the retry policy, pagination.
- [x] Typecheck, lint and build stay green.

## Resolution
Done.
- **Harness:**
  - `vitest.config.mts` (jsdom, v8 coverage, thresholds 90/90/85/85);
  - `test/setup.ts`: MSW server, where an unmocked request is an error (`onUnhandledFrame: "error"`), plus `next/navigation` and `next/link` stand-ins;
  - `test/next.tsx`, `test/render.tsx`, `test/msw/envelope.ts`, and `test/fixtures.ts` (shared with Playwright, AOS-311).
  - Scripts: `npm test`, `npm run test:coverage`.
- **Tests:** 18 files, **156 tests** — `lib/api` (12), `lib/query` (15), components (33), and every page: home, bills, briefings, subscriptions, transactions, anomaly review, settings, import, login, OAuth callback, onboarding, layout, route guard.
- **Coverage:** statements 98.2%, **branches 97.3%**, functions 99.5%, **lines 99.1%**.
- **Bugs the tests found, fixed here (each with its test):**
  1. Cash quick-add: Escape didn't close the sheet once focus left the inputs.
  2. Subscriptions: a price change with no percentage showed "↓changed". Now "price changed".
  3. Onboarding: if the Gmail sync didn't start, skipping SMS left an endless spinner.
  4. Onboarding: a refused Gmail connection did nothing. Both now move on.
- **Accessibility fixes:**
  - unlabeled inputs got accessible names (transaction filters; briefing day/time; quiet hours);
  - the login page reads its client id at render (same build-time inlining), so it is testable.
- **Found, not fixed (follow-ups in PROGRESS):**
  - the transaction list API sends amounts as floating-point numbers and no `nature` field (D-30); fix in AOS-307;
  - the onboarding copy describes an Android app (D-19 says iPhone);
  - the subscriptions "cancellation draft" modal can never open (dead code);
  - `npm audit`: 5 high, dev-only (ESLint chain → `braces`), already on main; the only fix npm offers is a breaking downgrade. Tracked as AOS-606.
