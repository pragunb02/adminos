## Design (approved by Pragun)
```
Web upload (file + optional PDF password)
  → API POST /api/v1/statements
  → pdf-parser (internal network only)
  → rows → IngestEvent (source=statement)
  → intake → pipeline → transactions
```
- **Parser:** a column-role detector based on header synonyms, so most banks need no per-bank code. Bank detection and account last 4 come from the header text.
- **Passwords** are used in memory only. **Files are discarded after parsing** (D-37).
- **Per-row fingerprint** (bank, account, date, amount, description, balance), so re-uploads and overlapping periods only add new rows.

## PR 1 — Python parser (done)
- **Rewrite:** `readers` (CSV with encoding and delimiter sniffing, XLSX, XLS, PDF with password), `table_mapper` (synonyms, multi-line narration, Indian amounts incl. Dr/Cr, parentheses and minus, 14 date formats, never guesses direction), `banks` (10 banks), `main`.
- **Endpoint:** `POST /v1/statements:parse` returns camelCase JSON with decimal strings, and stable error codes (`PASSWORD_REQUIRED`, `PASSWORD_INCORRECT`, `UNSUPPORTED_FORMAT`, `NO_TRANSACTIONS`, `FILE_TOO_LARGE`, `UNREADABLE`).
- **Privacy:** no logging of content, file names or passwords; errors never echo content.
- **Accuracy:** running-balance reconciliation (either sort order) warns when columns look mis-read.
- **Cleanup:** removed unused boto3/redis; added cryptography (AES PDFs), openpyxl, xlrd. Non-root container, no published port.
- **Tests:** 31 pytest tests (the repo's first Python tests) on synthetic HDFC CSV, SBI XLSX, ICICI, Kotak Dr/Cr and Axis password-protected PDF statements, plus API privacy and log checks. Image smoke test passed.
- **Bugs fixed during testing:**
  - `500.00Dr` (no space) wasn't recognised.
  - pdfplumber wraps password errors, so a wrong password reported "unsupported format".

## PR 2 — API, upload UI, retirements (done)
- **Domain port** `StatementParser`, with an `HttpStatementParser` adapter.
  - Sends a **generic file name** (`statement.<ext>`), so the user's real file name never leaves the API.
  - Uses JDK `HttpClient`, so no new dependency.
  - Stable error codes; an unreachable parser → `PARSER_UNAVAILABLE` (503).
- **`StatementImportService`:** rows → `IngestEvent`s (source=statement, midday IST, UPI ID from the narration, bank/balance metadata).
  - The **fingerprint has an occurrence counter**, so two identical lines in one statement (e.g. two ₹10 teas) are both kept while re-uploads add nothing.
- **`POST /api/v1/statements`:** multipart `file` + `password`, ≤20 MB → summary (bank, account, period, new, duplicates, skipped, warnings).
- **Retired** (D-37 makes them dead, and they leaked file names to logs):
  - `/upload/pdf`, the whole storage package (R2 + stub), the AWS SDK, R2 config/env, `enqueuePdfParse`
  - the Go PDF handler and the `pdf` worker type
- **Web:**
  - `/import` page: file + password (shown for PDFs or when required), with friendly password errors and a summary.
  - `api.upload()` for multipart with the same refresh/retry; nav link **Import**.
- **Fixes found along the way:**
  1. UPI ID regex accepted `-`, giving `upi-swiggy-swiggy@icici`. Fixed in **both** the statement and SMS parsers, with regression tests.
  2. **The API Docker build broke on this network:** the Gradle download (via GitHub) timed out inside Docker's build sandbox. The image now builds on the official `gradle:9.8.1-jdk25` image (Gradle preinstalled, pinned to the wrapper version). The wrapper network timeout was raised to 60 s for local use.
- **Tests:**
  - `StatementImportServiceTest` (4), `StatementRoutesTest` (3), `HttpStatementParserTest` (3), SMS VPA regression (1).
  - **`StatementImportIntegrationTest`:** Testcontainers builds the **real Python image** → Kotlin import → Postgres → pipeline → categorised transactions; re-upload → 0 new.
  - Unit 228, integration 42, Go green, web typecheck/lint/build ✅.
- **Live (compose):** the API (new image) reaches the parser at `http://pdf-parser:8000`; `/statements` without auth → 401; `/upload/pdf` → 404; the parser is unreachable from the host.
