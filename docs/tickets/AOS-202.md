## Design (approved by Pragun)
```
Web upload (file + optional PDF password)
  → API POST /api/v1/statements
  → pdf-parser (internal network only)
  → rows → IngestEvent (source=statement)
  → intake → pipeline → transactions
```
- **Parser:** a column-role detector based on header synonyms, so most banks need no per-bank code. Bank detection and account last 4 come from the header text.
- **Passwords** are used in memory only. **Files are discarded after parsing** (D-37).
- **Per-row fingerprint** (bank, account, date, amount, description, balance), so re-uploads and overlapping periods only add new rows.

## PR 1 — Python parser (done)
- **Rewrite:** `readers` (CSV with encoding and delimiter sniffing, XLSX, XLS, PDF with password), `table_mapper` (synonyms, multi-line narration, Indian amounts incl. Dr/Cr, parentheses and minus, 14 date formats, never guesses direction), `banks` (10 banks), `main`.
- **Endpoint:** `POST /v1/statements:parse` returns camelCase JSON with decimal strings, and stable error codes (`PASSWORD_REQUIRED`, `PASSWORD_INCORRECT`, `UNSUPPORTED_FORMAT`, `NO_TRANSACTIONS`, `FILE_TOO_LARGE`, `UNREADABLE`).
- **Privacy:** no logging of content, file names or passwords; errors never echo content.
- **Accuracy:** running-balance reconciliation (either sort order) warns when columns look mis-read.
- **Cleanup:** removed unused boto3/redis; added cryptography (AES PDFs), openpyxl, xlrd. Non-root container, no published port.
- **Tests:** 31 pytest tests (the repo's first Python tests) on synthetic HDFC CSV, SBI XLSX, ICICI, Kotak Dr/Cr and Axis password-protected PDF statements, plus API privacy and log checks. Image smoke test passed.
- **Bugs fixed during testing:**
  - `500.00Dr` (no space) wasn't recognised.
  - pdfplumber wraps password errors, so a wrong password reported "unsupported format".
