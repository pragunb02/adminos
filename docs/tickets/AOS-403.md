## Description
Many Indian banks send alerts on WhatsApp. WhatsApp has no API for reading chats, but every chat can be exported (iPhone: a `.zip` with `_chat.txt`; Android: a `.txt`). Import the bank messages in such an export as transactions and mandate updates, through the same rules as bank SMS.

## Acceptance criteria
- [x] `POST /api/v1/imports/whatsapp` (multipart `file`, signed in) takes a `.txt` or a `.zip` export.
- [x] **Formats:** iPhone `[16/10/26, 9:12:03 AM] Sender: text` (with its invisible LRM marks and narrow no-break space) and Android `16/10/26, 09:12 - Sender: text`, 12- or 24-hour, `/`, `.` or `-` dates, 2- or 4-digit years.
- [x] Multi-line messages are joined. System lines ("end-to-end encrypted") are counted, not parsed. Impossible dates or times (31/02, 25:00) are counted as unreadable.
- [x] **Day/month order** comes from the file (a first number over 12 means day first, a second over 12 means month first); an ambiguous file is day first (India).
- [x] Times are read in the user's time zone; a message dated in the future (wrong date order, clock) is skipped with that reason, not an error.
- [x] **Only bank senders are parsed**, by display name: known banks (HDFC, SBI / State Bank, ICICI, Axis, Kotak) use their own parser; other names with bank/card/credit/finance use the generic one. People and groups are never parsed, so "I paid 500" from a friend can't become a transaction.
- [x] Bank messages go through the SMS rules (OTP, failed, mandate notice, drop rules, bank parser), and become `whatsapp` intake events or mandate updates.
- [x] **Idempotent:** each message's reference is a fingerprint of sender, time and text. Re-importing the chat, or a longer export of it, adds only new messages; mandate notices aren't applied twice.
- [x] **Limits:** 20 MB upload; at most 10 MB of chat text, also inside a zip (read capped, so a zip bomb never inflates fully); media and macOS metadata in the zip are skipped unread.
- [x] **Errors** with clear codes: empty file, not a chat (binary), zip without a chat, damaged zip (422), too large (413), no file (400), not signed in (401).
- [x] The chat text is never stored or logged (D-33); `ChatMessage.toString` is redacted.
- [x] **Response:** messages, from banks, accepted, duplicates, mandates, ignored by reason, unreadable lines.
- [x] **Web:** an "Import a WhatsApp bank chat" section on Import, with export steps (Without media), the counts, skipped reasons, unreadable-date note, and a hint when no message came from a bank.

## Design
- **Sender options:**
  1. **Bank senders by display name only** (chosen): safe by default; a missed bank is one entry in `BankSenders`.
  2. Parse every message: a friend's message could become a transaction.
  3. Ask the user which sender is the bank: extra step; a later option if names prove unreliable.
- **Parsing options:**
  1. **Reuse the SMS registry through `parseFromBank(text, bankCode)`** (chosen): one set of rules; WhatsApp alerts are the SMS text.
  2. A separate WhatsApp parser set: duplicated rules that drift.
- **Fingerprint:** sender + time + normalised text. The same alert received by SMS too is matched by the pipeline's cross-source dedup (D-38), not by the fingerprint.
- **Decision:** D-66.

  - Parser: iPhone and Android formats, AM/PM edge (12 AM), multi-line, system lines, day/month detection, unreadable lines, dotted dates, redaction, sender matching.

## Risks / notes
- Bank display names vary; an unrecognised bank without bank/card/credit/finance in its name is skipped (it shows as messages but 0 from banks). Add it to `BankSenders`.
- The export's times have minute (Android) or second (iPhone) precision and the phone's own time zone; the user's zone is assumed.
