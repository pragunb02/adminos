## Audit findings
- **JSON casing:** the API emits camelCase for all 46 DTOs, and the web reads camelCase for all 89 fields. Only 3 request bodies were snake_case (`redirect_uri`, `source_type` ×2).
  - Pragun first chose snake_case on my recommendation, which rested on an incomplete look at the requests only. After the audit we switched to **camelCase** (D-31).
- **Contract bugs found and fixed:**
  1. `GET /transactions`:
     - `merchant=` was ignored (the API read `q`).
     - `from`/`to` dates were rejected (the API required full instants).
     - `is_recurring` → `isRecurring`.
  2. `GET /subscriptions?status=flagged` → 400 (no such status). The Flagged tab never worked. Flagged is now a `flagged=true` filter in the repository, so pagination stays correct.
  3. **Pagination was broken whenever the database was used.** Routes returned raw timestamps; Exposed repositories required Base64 cursors; in-memory accepted raw. `CursorCodec` moved to `domain/common`: routes encode it, and both repository kinds decode it.
  4. Invalid enum values returned messages leaking class names, and the anomaly status was silently ignored.
- **Fix:** typed `QueryParams` helpers (`enumParam`, `booleanParam`, `uuidParam`, `limitParam`, `rangeStartParam`/`rangeEndParam`, `dateParam`). Bad input gets a clear 400 (`VALIDATION_003`) listing the allowed values.
  - Dates mean whole days in Asia/Kolkata until per-user timezones arrive (AOS-120).

## Resolution
- **Web:** `redirectUri`, `sourceType` ×2, `isRecurring`; subscription tabs map to `status=active`, `flagged=true`, `status=cancelled`.
- **Tests:**
  - `FinancialRoutesContractTest` (6): IST day ranges, merchant/isRecurring filters, cursor page 1 → 2 with no overlap, enum 400s, invalid date/bool/limit/cursor 400s, flagged filter.
  - New integration test: cursor pagination over Postgres.
- Unit 154/154 · integration 32/32 · web typecheck/lint/build ✅.
- **Noted for AOS-301:** `/transactions/summary` sums money as `Double`, and the money DTOs use `Double`. Moving to exact decimals belongs with the analytics API work.
