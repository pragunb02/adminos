## Contract
```
POST /api/v1/ingest/events        (auth; 1..100 events)
{ "events": [{ "source": "sms|gmail|statement|whatsapp|manual", "sourceRef": "<unique per source>",
               "occurredAt": "2026-10-01T09:12:00+05:30", "direction": "debit|credit", "amount": "249.50",
               "currency": "INR", "merchantRaw": "…", "accountHint": "1234", "paymentMethod": "upi", "upiVpa": "…" }] }
→ 202 { "accepted": n, "duplicates": m }
```
- Amounts are **decimal strings**: a JSON number is rejected.
- `occurredAt` needs an offset.
- At most 10 min in the future (clock skew).
- **Idempotent** per (user, source, sourceRef), so retries are safe.

## Resolution
- **V9 `ingest_events`:** append-only, unique (user, source, source_ref), partial index on pending.
  - It acts as the **outbox** (D-27): events stay `pending` until the Milestone 2 processor takes them.
  - It never stores raw text (D-33).
- **Domain:**
  - `IngestEvent` validates itself: amount > 0 with scale ≤ 2, ISO currency, 4-digit account hint.
  - `IngestEventService` enforces batch limits and future dates, and counts duplicates within a batch.
  - In-memory and Exposed repositories (Exposed: `insertIgnore` → `ON CONFLICT DO NOTHING`).
- **API:** `ingestEventRoutes`, plus a DTO → domain mapper that names the bad field (`events[0].amount: …`).
- **Fixed for every endpoint:** an undecodable body (bad JSON or wrong types) was a **500**; now it's a 400 `VALIDATION_004`.
- **Tests:**
  - `IngestEventServiceTest` (7)
  - `IngestEventRoutesTest` (7: 202 with counts, retry is a duplicate, 401, number amount → 400, malformed JSON → 400, field-named 400s, raw text not stored)
  - `IngestEventRepositoryIntegrationTest` (4)
  - Unit **179/179**, integration **36/36**.
- **Scope note:** `/ingest/sms` still feeds the Go worker. Converting it to an adapter waits for the processor decision (AOS-201).
