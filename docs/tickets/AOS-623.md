## Description
Attack our own stack as an outsider would, before go-live: a scripted, local-only ZAP baseline and black-box probes, plus the manual checklist for what needs the real signed-in stack. Every finding gets a ticket and is fixed or explicitly accepted.

## Acceptance criteria

Items are marked **auto** (covered by probes or attack suites, all passing) or **owner** (need the real devices, Google account, passkey or edge).
- [x] `scripts/security/zap-baseline.sh`: ZAP baseline against a throwaway local stack that publishes no host port (refuses otherwise, fail closed), digest-pinned images, full cleanup; not in CI (D-150).

- [x] Run locally on main 827d7321: ZAP 0 FAIL (web 6 WARN types, API 1, triaged); probes 34/35; exposure and hardening checks green; attack suites green.
- [x] One ticket per finding: AOS-643 (accepted, D-151), AOS-644 (fixed here). ZAP warnings triaged and accepted in D-151.

## Security
- **Exposure:** the scan stack publishes nothing. ZAP and curl join its internal `edge` network; the script checks the rendered compose config and refuses any published port, or a config it can't render.
- **Data:** random throwaway secrets and an empty database; everything is removed after the run (containers, volumes, networks, built images).
- **Images:** ZAP and curl are pinned by digest (D-99).
- **Authenticated testing:** left to the attack suites and the owner checklist; no tokens are made by hand.
