## Description
The Review page gets a **"Check these categories"** queue: the guesses the learned categoriser (AOS-707) and the AI fallback (AOS-512) are least sure of, ordered by **uncertainty × amount**.
- **Answering:** confirming or correcting is one tap, and the answer becomes a remembered correction (D-41). It waits 5 seconds for Undo before it is sent (D-49).
- **Golden set:** optionally, a scrubbed copy goes into the user's **local** golden set. It can be exported and scored with the harness, and it is never committed.

## Why
- **Active learning:** asking about the most uncertain items cuts labelling effort compared with random review (Settles 2009, research report §9).
- **Weighting by amount:** a big uncertain spend matters more than a small one.
- **Answers teach:** each answer improves the payee's category at once (remembered rule) and the model at its next training (AOS-707).
- **Real-shaped data:** the golden set (D-61) needs real-shaped rows, and these must never carry personal data into a public repo.

## Scope
- **In:**
  - the queue (API + domain): reading `metadata.learned` and `metadata.ai`, eligibility and ordering;
  - the answer endpoint (a remembered correction, audited);
  - the scrubber and the local golden set (migration, export, delete);

## Design
- **Context:**
  - AOS-707 writes `metadata.learned = {status, category, confidence, cues, alternatives, model, at}`, with source `learned` when applied. This task adds `alternatives`, the model's next two categories.
  - AOS-512 writes `metadata.ai = {status, category, confidence, reason, model, at}`, with source `ai` when applied. It is only read here (AOS-702 owns that code).
  - Corrections (D-41) already exist via `PATCH /transactions/{id}`.
  - The Review page already has a 5-second Undo for pair suggestions (D-49).
- **Where the queue's state lives. Options considered:**
  1. **Derived from the transactions (chosen):**
     - a question is open while the guess is still what the row shows; answering makes it a correction (source `user`), which closes it;
     - there is no new state, so nothing can drift, and a later model or AI run adds questions automatically.
  2. A `review_items` table written by the models: explicit state, but every writer must keep it in sync with corrections, re-labels and retraining. That is a second source of truth.
- **Answer endpoint. Options considered:**
  - (a) **A dedicated `POST /categories/review/{id}` (chosen):** one call per answer, which keeps Undo simple. It always remembers (D-41), can add the golden copy in the same call, and is audited with `via: review`.
  - (b) Reuse `PATCH /transactions/{id}` plus a second call for the golden copy: two calls to undo or fail half-way, and the route calls the repository directly (legacy).
- **Uncertainty measure. Options considered:**
  - (a) **Least confidence (1 − p) × amount (chosen):** it works the same for both models; the AI stores only its top answer, so margin or entropy can't be computed for it.
  - (b) Margin (p1 − p2) or entropy: better for the learned model alone, but not comparable across the two.
- **Local golden set. Options considered:**
  - (a) **Rows in the user's own database, exported as `golden.csv`-shaped CSV, scored with `-PlocalGolden` (chosen):** they never touch the repo, survive restarts, and are deleted with the user. Committing is a separate, manual step.
  - (b) Append to `golden.csv` directly from the API: personal data one `git add` away from a public repo. Rejected.
  - (c) A file on the server's disk: lost on container rebuilds, and outside user deletion.
- **Scrubbing. Options considered:**
  - (a) **Mechanical rules, plus refusal where a person is likely, plus "review before commit" (chosen).** A person's name can't always be recognised, so the safety comes from never committing automatically.
  - (b) Reuse `AiPrivacyGate`'s business evidence: it belongs to AOS-702's in-flight refactor, and it is tuned for what may be sent to a cloud model, not for what may be kept.
- **Decision:** 1, (a), (a), (a), (a) (D-72). **Patterns:**
  - Specification: `CategoryQuestion.of` and the scrubber's refusals;
  - Repository: `GoldenCandidateRepository`, InMemory and Exposed (same tests);
  - in the web, one `usePendingAction` hook for every Undo-able decision on the page.
- **Extensibility:**
  - a new model's guesses join the queue by writing the same `{status, category, confidence}` shape under its own metadata key, plus one `GuessSource` entry;
  - a new refusal is one `ScrubRefusal`;
  - the queue size and window live in `ReviewSettings`.
- **Impact:**
  - **Domain:** `domain/financial/review/`; `LearnedCategorizer` gains `alternatives`.
  - **Infrastructure:** `GoldenCandidatesTable`, `ExposedGoldenCandidateRepository`.
  - **Schema:** V43.
  - **API:** five endpoints.
  - **Harness:** `-PlocalGolden`.
  - **Web:** Review page, `CategoryQuestions`, `usePendingAction`, `lib/categoryReview.ts`, types, MSW and e2e defaults.
  - **Repo:** `.gitignore`.
  - No Go change.
- **Diagram:**
```mermaid

  A[AI job: metadata.ai] --> T
```

## Growing a local golden set (how-to)
1. **Answer with a copy.** On Review, tick **"Also keep a scrubbed copy in my local test set"** and answer questions. Each answer that can be scrubbed is kept in your database (`golden_candidates`); the page says when one isn't, and why.
2. **Download.** Use **"Download CSV"** on Review (or `GET /api/v1/categories/golden.csv` while signed in). Save it as `services/api/local/golden.local.csv`; that folder and `*.local.csv` are git-ignored.
3. **Score it locally:** `cd services/api && ./gradlew -q categorizationReport -PlocalGolden=local/golden.local.csv`.
   - It prints the rules and the rules + learned tables for your rows.
   - Nothing is written or gated, and nothing leaves the machine.
4. **Promoting rows to the shared golden set is manual and optional.** Follow AOS-511 "Growing the golden set":
   - check every row by hand: no person's name, no phone number, no reference;
   - re-label the ids `P###`;
   - append to `services/api/src/main/resources/categorization/golden.csv` and re-record with `-PwriteBaseline`.
   
   Never commit the downloaded file itself.
5. **Remove a row** with `DELETE /api/v1/categories/golden/{id}`. Deleting the account removes them all.

## Risks / notes
- **Names of people in the local set:**
  - a payee answered with a real category could still be a person (a friend's tiffin service);
  - the set is local, deleted with the user, and its export says never commit it as is;
  - promoting rows is a hand-reviewed step.
- **Queue reads the last 90 days (up to 2,000 rows)** and filters in memory. That is fine for one person. A `metadata ? 'learned'` index and query would be the scale-up path.
- **AI metadata shape:** read only, tolerant of missing or changed fields. If AOS-702 renames `metadata.ai`, AI questions disappear quietly from the queue. The learned ones still work. Worth a contract test once AOS-702 lands.
- **Migration number:** `V43` (renumbered from the tentative `V32` at integration). Stacked on V42 (AOS-707).
