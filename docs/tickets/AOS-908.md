## Description
Home leads with the **savings rate**, (income − spend) ÷ income per month, and its 12-month trend. Under it, "what this could become": last month's leak spend invested monthly as a SIP, over 5 and 10 years, with the return and inflation assumptions shown and editable and the formula under "How we got this". A too-little-data state when there's no income yet.

## Why
D-80: the savings rate is the one number that links spending to wealth; the projection makes a leak's cost tangible.

## Acceptance criteria
- [x] Per month: income = the `income` nature (salary and other income); transfers and refunds are neither; spent = spend − refunds; the same series as the console (D-45/D-46).
- [x] Rate = (income − spent) ÷ income; none for a month with no income (never a division by zero); negative when spending exceeds income.
- [x] Headline: this month if it has income yet, else the latest month that does; trend vs the month before in points with an arrow and words.
- [x] "What this could become": last full month's leak spend (AOS-902 total) as a monthly SIP at 12% a year, 6% inflation by default; both editable (0..30 / 0..20); 5 and 10 years; contributions, future value and today's money; the formula shown.
- [x] Too little data: no month with income in 12 months → a message saying what's needed; no projection when last month had no leak spend.
- [x] Lines for change over time with a sentence and a table (D-49); Indian formatting.

## Design
- **Options considered:**
  1. **Compute in the browser** from the analytics series: duplicates money rules and BigDecimal care in TypeScript; the projection would be a client-side number (D-67 wants numbers from deterministic server code).
  2. **A coach endpoint over `AnalyticsService` + `LeakService`** (chosen): one definition of income and spend; the SIP maths in Kotlin with BigDecimal (34-digit precision), tested against independent values.
  3. **Store monthly snapshots:** history that can drift from corrected transactions.
- **Decision:** option 2. **Formula:** FV = P × ((1 + r)ⁿ − 1) ÷ r × (1 + r), r = annual ÷ 12, n = 12 × years (payment at the start of each month); r = 0 → P × n; today's money = FV ÷ (1 + inflation)^years. Defaults: 12% (a common long-run equity SIP assumption) and 6% inflation, labelled as assumptions, not advice.
- **Extensibility:** another horizon is one entry in `Sip.YEARS`; another "could become" (e.g. a goal's saving) reuses `Sip.horizon`.
- **Impact:** `domain/coach/savings/*`, `GET /api/v1/coach/savings`, web `lib/savings.ts`, `components/savings/SavingsCard.tsx` at the top of Home. No schema change.

## Security (D-100, docs/ENGINEERING.md §4a)
- **Exposes:** one authenticated read route.
- **Abuse:** signed out → 401 (route test); scoped to the token's user (another user gets "too little data", tested); `months` (3..24), `annualReturnPct` (0..30) and `inflationPct` (0..20) are regex/range-checked → 400 naming the parameter, injection text included; BigDecimal maths with bounded inputs (no overflow or huge exponents: years ≤ 10 here, ≤ 50 by contract). Web renders server text as text (Playwright check with an HTML-looking error).
- **Data / logs / dependencies:** nothing stored or logged; none new.
