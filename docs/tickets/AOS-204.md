## Description
- Add a cash payment in two taps: type the amount, then tap a category.
- ATM withdrawals become a move of money to cash, so cash spending isn't counted twice.

## Why
- Without this, cash spending is invisible (D-19, P0).
- If ATM withdrawals also counted as spending, every logged cash payment would count twice.

## Scope
- **In:**
  - `POST /api/v1/transactions/cash`, through the common intake and pipeline (D-21);
  - the chosen category is kept;
  - an idempotency key per entry;
  - cash is never matched as a duplicate;
  - ATM withdrawal → transfer (D-42);
  - a "+ Cash" button on every page.
- **Out:**
  - a cash balance / wallet view (later, AOS-3xx);
  - cash income;
  - editing an entry (the existing transaction PATCH covers the category).

## Acceptance criteria
- [x] Amount + category saves a cash transaction (spend, `paymentMethod = cash`, `categorySource = user`).
- [x] The same entry sent twice (double tap or retry) is saved once.
- [x] Bad input gets a 400 naming the field: amount ≤0 or too large, unknown category, note too long, a time in the future.
- [x] A cash entry is never merged with or suggested as a duplicate of a bank transaction.
- [x] ATM withdrawals (SMS or statement narration) are transfers, not spending.
- [x] Web: "+ Cash" → amount → tap a category = saved (built, typechecked, linted; live click-through waits for login, AOS-112).

## Design (approved by Pragun 2026-10-16)
- The cash adapter builds a MANUAL ingest event with direction debit, method CASH, the note as merchant, and the category.
  - V16 adds `ingest_events.category`.
  - `ToTransactionStep` carries the category as user-set; `CategorizeStep` leaves user-set categories alone.
- `TransactionMatcher` skips cash on either side.
- `TransferDetector.isCashWithdrawal` sits next to the card-bill check (narration patterns: `ATM`, `ATW-`, `NWD-`, `CASH WDL`, `CASH WITHDRAWAL`).
