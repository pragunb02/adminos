## Description
Upgrade `apps/web` to Next 16, React 19, Tailwind 4, ESLint flat config, the newest supported TypeScript, and a Node 24 LTS image.

## Acceptance criteria
- [x] Latest stable versions, exact pins (Next 16.4.2, React 19.3.1, Tailwind 4.3.3, ESLint 10.12.0, eslint-config-next 16.4.2, @types/react 19.3.0, @types/node 24.19.2, postcss 8.5.30)
- [x] TypeScript at the newest *supported* version: **6.0.3**, because typescript-eslint supports `<6.1.0` and doesn't support TS 7 yet (D-29)
- [x] `next build` ✅, `tsc --noEmit` ✅, `eslint .` 0 errors ✅, `docker build` ✅

## Implementation
- **Next 16:**
  - `middleware.ts` → `proxy.ts`, with `export function proxy` (official rename).
  - `/anomalies/[id]` uses `useParams()` (client), so no async-params change was needed.
- **TypeScript:** `tsconfig` target `es5` → `ES2022` (TS 7 removed ES5; ES2022 matches Next 16's browser baseline).
- **Tailwind 4:**
  - CSS-first `@import "tailwindcss"` and `@tailwindcss/postcss`; `tailwind.config.ts` and autoprefixer removed.
  - Class renames: `shadow-sm` → `shadow-xs`, `rounded` → `rounded-sm`.
  - Base-layer compatibility keeps v3's gray-200 default border and the pointer cursor on buttons.
- **ESLint 10:** `eslint.config.mjs` (next core-web-vitals + typescript); `lint` and `typecheck` scripts.
- **Lint:** it had never run before (there was no config). New React 19 hooks rules flag setState-in-effect data fetching on 7 pages (8 errors). The rule is set to **warn** until **AOS-308** (D-29).
- **Image:** `node:24-alpine`. Repo `.gitignore` now ignores `.next/`, `next-env.d.ts` and `*.tsbuildinfo`; the tracked `tsconfig.tsbuildinfo` was removed.
