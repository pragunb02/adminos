## Description
Add `NEXT_PUBLIC_GOOGLE_CLIENT_ID` to .env.example and as a compose build arg; set the API URL to http://localhost:8080 at build time; enable CORS with credentials for APP_URL.

## Why

## Resolution
- **Design (D-32, chosen by Pragun): same-origin proxy.** `next.config.mjs` rewrites `/api/*` to `API_INTERNAL_URL` (default `http://localhost:8080`; the compose image uses `api-server:8080`). `api.ts` uses relative URLs. No CORS is needed.
- **Config:** the repo-root `.env` is the single source (`loadEnvConfig`). `GOOGLE_CLIENT_ID` feeds `NEXT_PUBLIC_GOOGLE_CLIENT_ID`. If it's missing, the login button is disabled with a clear message (no redirect to Google with an empty client id).
- **Found and fixed while verifying live:**
  1. **The web login guard (`proxy.ts`) also covered `/api/*`**, so `POST /api/v1/auth/google` (no cookie yet) was redirected to `/login`. **Login could never have worked.** `/api/*` is now exempt (the API authenticates itself).
  2. **401s had an empty body** (Ktor auth challenge), so `api.ts` `response.json()` threw.
     - The API now returns the standard envelope for any bare 401 (`AUTH_002`). Specific 401 codes such as `AUTH_001` are preserved (tested).
     - `api.ts` tolerates non-JSON responses.
  3. **Client IP:** behind the proxy, the API saw the proxy's IP.
     - Added Ktor `XForwardedHeaders` (`useLastProxy`) and one `call.clientIp` helper, used by the rate limiter, login, sessions and audit (7 sites).
     - **Live test:** Next passes a client-supplied `X-Forwarded-For` through unchanged, and can't see the client IP itself.
     - So a correct client IP requires an **edge proxy** that sets XFF (recorded as a launch requirement in AOS-605). Locally, all traffic is from 127.0.0.1 and ports are bound to localhost, so there's no impact.
- **Docker/compose:** web build args (`API_INTERNAL_URL`, `NEXT_PUBLIC_GOOGLE_CLIENT_ID`); image runs as `node`; `.dockerignore`; `NEXT_PUBLIC_API_URL` removed. `next.config.js` → `next.config.mjs` (ESM; lint rule).
- **Verification:**
  - API unit **158/158** (+3 ClientIp, +2 auth envelope).
  - Live: `GET /api/v1/transactions` via :3000 → 401 envelope from the API; `POST /api/v1/auth/google` via :3000 reaches the API (camelCase `redirectUri` accepted, fails only at Google with a fake code); pages still redirect to `/login`.
  - Web image: client id inlined, rewrite → `api-server:8080`, non-root.
