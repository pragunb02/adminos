## Description
The legacy weekly briefing (in the Go worker, using Claude) was never triggered, and its data query returned zeros. The briefing is now made in the API from the same numbers the console shows. A fixed template writes the text, and it's delivered on the user's chosen day and time.

The task also fixes the queue publisher, which turned every payload value into a string, breaking the Go handlers' typed payloads.

## Acceptance criteria
- [x] **When:** on the user's `briefingDay` and `briefingTime`, in their own zone (an invalid zone falls back to India time).
  - The briefing covers the 7 days before that day.
  - If the app was down at that moment, it catches up the same week.
  - There's one briefing per (user, week); `uq_briefing` backs this up.
  - There's no briefing for a week that ended before the user signed up, or when briefings are switched off.
- [x] **What it says** (every number is a fact from analytics or dues):
  - spent, compared with the week before (more, less, the same, or nothing before);
  - the top 3 categories;
  - the biggest payee, with its payment count;
  - money received;
  - dues in the next 7 days (count, total, the first one);
  - open unusual charges;
  - subscriptions flagged;
  - unused AutoPay mandates.
  - A quiet week says so; singular and plural read correctly; amounts use Indian formatting (`formatInr`).
- [x] **Saved:** the text, a structured copy (exact money strings), totals and counts, `modelUsed = deterministic`, and `promptVersion = weekly-v1`.
- [x] **Notification:** a BRIEFING notification ("Your week: ₹4,100.50 spent"), held for quiet hours like other non-critical types. A tap opens `/briefings`.
- [x] **Job:** `weekly-briefing` runs every 15 minutes for active users and is idempotent.
- [x] **Queue publisher:** payload values keep their JSON types (numbers, booleans, lists, objects, null) instead of all becoming strings.

## Design
- **Options considered:**
  1. **A deterministic briefing in Kotlin** from `AnalyticsService` and `DuesService` (chosen). The numbers can't be wrong or invented, it is testable, and it needs no API key.
  2. **The legacy Go + Claude path, with a real data query.** That means a second copy of the analytics SQL in Go and an LLM writing money facts. Pragun is concerned about hallucination (2026-10-16), and accuracy has no harness yet (proposed AOS-511).
  3. **Deterministic facts plus an AI rewrite of the wording only.** This is possible later, once an evaluation harness exists.
- **Decision:** option 1 (D-57). **Patterns:**
  - a parameter object for the sources (`BriefingSources`);
  - a pure writer (`BriefingWriter`);
  - a polling job (`Schedule.Every`), where the service decides per user.
- **Extensibility:** a new briefing line is one fact in `BriefingFacts` plus one line in the writer. A monthly briefing is the same service with a month range and `BriefingType.MONTHLY`.
- **Impact:**
  - `domain/agent/briefing/*`;
  - `BriefingRepository.findByUserAndPeriod`;
  - `formatInr()` in `domain/common/Money.kt`;
  - `AsynqPublisher` payloads (via `JsonColumns`);
  - a `briefing` tap URL for Web Push;
  - Koin wiring.
  - No schema change: V23 was reserved but isn't needed.
