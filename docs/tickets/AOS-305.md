## Description
Frame **M/Spending** of `docs/design/console.md`.
- **`/spending?p=&d=&view=categories|merchants`:** the same period switcher as Home (the URL parameters are shared, a refinement of the spec's `?m=`), and the period total against the same days before.
  - **Categories:** every category as a sorted bar with ₹, share and the change; a row opens its detail.
  - **Merchants:** every merchant with category, number of payments, average per payment and total.
- **`/spending/category/{cat}`:**
  - the category's spent this period against the same days before;
  - its 6-month trend (line + table);
  - its top merchants;
  - its transactions, with a link to the filtered Activity feed.
- **API:** an optional `category` filter on `GET /analytics/series` and `/analytics/merchants`. Same rules (D-46); an unknown category is a 400 naming the parameter.

## Acceptance criteria
- [x] The view and period are in the URL: switching views and periods pushes history; back/forward/refresh restore them.
- [x] Category rows link to their detail, keeping the period; the detail's back link returns to the list.
- [x] Refund-only categories show a negative value labelled "refunds only" (D-46).
- [x] States: loading, empty period, error with retry; an unknown category says so.
- [x] API: filtered series and merchants are tested in-memory and on Postgres (SQL = in-memory).
- [x] Unit + Playwright tests (incl. a view/period back-forward chain), axe clean; coverage gates hold.
