## Description
Make authorization regressions impossible to merge quietly:
- an API test that reads every registered Ktor route and fails CI if one is not behind a session and not on a reviewed allowlist;
- per-resource IDOR tests (another user's IDs are 404, indistinguishable from missing ones, and nothing changes);
- Playwright attack specs in `apps/web/e2e/security.spec.ts` that other features extend (D-100 §4a).
Also fixes AUD-13 (the web guard prefix-matched public paths).

## Acceptance criteria
- [x] Route inventory from the real app's routing tree; any route not in `authenticate("auth-jwt")` and not allowlisted fails, with a message saying what to do. Allowlist entries each name their replacing control; stale entries fail.
- [x] Every protected route answers 401 without credentials; a device token (header or cookie) never opens a session route; a session token never opens the device route.
- [x] IDOR: transactions, subscriptions (get, keep, cancel guidance), bills, anomalies (get, resolve), suggestions (confirm, reject), documents (get, file, patch, delete), connections (disconnect, sync), sync sessions, device tokens, auth sessions, push subscriptions → 404 with the same error code as a random ID; Alice's data unchanged; 22 list endpoints show Bob nothing of Alice's.
- [x] Playwright: signed out, every page (and look-alike paths) redirects to login; forged tokens (wrong secret, expired, `alg: none`, device `typ`, other issuer, tampered payload, garbage) are refused; another user's transaction is 404 and unchanged; a non-owner sees "This AdminOS is private"; no token or secret value in cookies readable by script, storage, DOM or same-origin bundles.
- [x] Security headers spec: added with the headers themselves in AOS-618.
- [x] AUD-13 fixed: public pages matched exactly; empty cookie = no session.

## Design
- **Context:** routes are registered by six domain modules; nothing proved each is protected. Ownership checks exist per route but were never attacked together.
- **Options considered:**
  1. **Introspect the real routing tree** (chosen): `routingRoot.getAllRoutes()`, walk each leaf's selectors (method, path segments, `AuthenticationRouteSelector` names). Unknown selector types fail the test, so new routing constructs must be reviewed. Plus a behavioural pass (unauthenticated calls → 401) so "declared but not enforced" (e.g. optional auth) also fails.
  2. A hand-maintained list of routes to probe: forgets new routes — exactly the failure we're guarding against.
  3. A production "public route" annotation: puts test policy in production code and still needs the inventory to enforce it.
- **IDOR:** seed Alice's data straight into the app's own repositories (Koin), attack as a signed-in Bob through HTTP, compare each answer with the one for a random ID (no enumeration oracle), then re-read Alice's data.
- **Playwright:** one spec file, both modes: real-API attacks in `full-stack`, mocked ones elsewhere; exported `PAGES` and `SECRET_PATTERNS` are the extension points.

## Security (D-100 §4a)
- **Exposes:** nothing (tests, plus a stricter web guard).
- **Abuse covered:** a new unauthenticated route; optional or mis-scoped auth; device/session token confusion; another user's IDs (read, change, delete, enumerate); guard path tricks; forged/tampered/expired tokens; secrets reaching the browser.
