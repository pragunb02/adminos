## Description
After CI landed (AOS-622), GitHub's own "CodeQL" summary check reports `neutral` ("1 configuration not found") when main has no analysis to compare with. `scripts/merge-pr.sh` required **every** check to be `success`, so such PRs could never merge.

## Acceptance criteria
- [x] Every check in main's `.github/required-checks.txt` must be `success`.
- [x] Any other check may be `success`, `neutral` or `skipped`; a failure, cancellation, timeout or required action on any check still refuses the merge.
- [x] Failures are listed once, by name and conclusion.
- [x] Tests: neutral and skipped non-required checks merge; a failed non-required check refuses; a required check that is only neutral refuses. `merge-pr.test.sh` 27, `review-status.test.sh` 9.

## Security
The gate stays fail-closed on anything that went wrong. Only "didn't apply" results (neutral/skipped) on checks branch protection doesn't require are accepted. Branch protection still independently requires the listed checks.
