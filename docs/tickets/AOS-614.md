## Description
**Finding (critical, found 2026-10-17 while reviewing for D-78):** `AuthService.loginWithGoogle` created a new user, with role OWNER, for **any** Google account with a verified email. Each user's data was scoped to them, but anyone who could reach the site could sign up and use it, and every new account was an "owner". For a single-owner site (D-78) that is an open door.

## Acceptance criteria
- [x] Only the Google account whose verified email equals `OWNER_EMAIL` can sign in (trimmed, case-insensitive).
- [x] **Pinned:** once that email has signed in, a different Google account presenting the same email is refused.
- [x] **Fail closed:** with no `OWNER_EMAIL`, nobody can sign in. With a database (`DATABASE_URL`), start-up stops without a valid `OWNER_EMAIL`; docker-compose requires it.
- [x] A refused sign-in is `403 USER_003 "This AdminOS is private"`: no user, session or cookies are created, and the owner's email is never revealed.
- [x] Refreshing a session of anyone who isn't the owner revokes it (e.g. after `OWNER_EMAIL` changes).
- [x] The unverified-email check still runs first.
- [x] **Web:** the login page says "This AdminOS is private. Only its owner can sign in."

## Design
1. **Allowlist one email, pin its Google ID** (chosen): simple, fail closed, survives email reuse.
2. Pin a Google `sub` in config: safest, but the owner can't know their `sub` before the first sign-in.
3. Google OAuth consent screen in "Testing" with one test user: an extra outer layer, but sensitive-scope refresh tokens then expire every 7 days, which breaks Gmail sync. It stays a possible extra layer, not the control.

## Verification
- **API:** `OwnerOnlySignInTest` (owner signs in; stranger refused with nothing created; same-email impostor refused after pinning; no owner → nobody; unverified first; non-owner refresh revoked; policy normalising/validating; `OWNER_EMAIL` required with a database). Route test: 403 `USER_003`, no cookies, owner never named. Existing auth tests now configure the owner. `./gradlew test integrationTest koverVerify` passes.
- **Web:** login and callback tests for the private message; 360 unit tests, 98.5% lines; Playwright 270 + 7 skips.
- Also fixed a race in `e2e/gmail.spec.ts` (counted the second POST once instead of polling; 75/75 on repeat, then fixed).

## Risks / notes
- Access JWTs already issued to a non-owner stay valid until they expire (`ACCESS_TOKEN_TTL`, 1 h); none exist yet because nothing is deployed. The full security audit (AOS-615) reviews token lifetimes and per-request checks.
