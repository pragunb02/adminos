## Acceptance criteria
- [x] **Web headers (AUD-07):** per-response CSP with a script nonce and `strict-dynamic`, no `unsafe-inline` for scripts, `frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'none'`; X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy, COOP, CORP on every response (static files included); HSTS when `APP_URL` is https; no `X-Powered-By`.
- [x] **API headers:** `default-src 'none'` CSP, nosniff, DENY, no-referrer, CORP/COOP, Permissions-Policy, `Cache-Control: no-store`, HSTS for https. CORS removed (AUD-17).
- [x] **CSRF (AUD-08):** every cookie-authenticated POST/PUT/PATCH/DELETE needs `Sec-Fetch-Site: same-origin` or `Origin` = the app's origin; anything else, or neither, is 403 `CSRF_001`. Header-token requests and safe methods are unaffected.
- [x] **Sign-in (AUD-06/19):** `GET /auth/google/start` issues a single-use server-side state + PKCE (S256) bound to the browser by an HttpOnly cookie; `POST /auth/google` needs body state = cookie state, consumes it, and sends the verifier to Google. Identity scopes only, no offline access, no forced consent.
- [x] **Lockout (AUD-16):** after 5 refused sign-ins in 15 min a client waits 1 min, doubling to 1 h; 429 `RATE_002` with `Retry-After`; the owner's success clears it. Rate limiter bounded (no unbounded key map), no `!!`, per application (no global counters).
- [x] **Client IP (AUD-03):** `TRUST_FORWARDED_FOR` (default false): the API ignores `X-Forwarded-For` unless an edge that appends it is declared.
- [x] **JWT (AUD-14):** exactly HS256, no `crit`, `exp` required, `iat` not in the future.
- [x] **Errors (AUD-15):** library and JDK messages (class names, quoted input, stack text) never reach clients; control characters stripped; our own field messages kept.
- [x] **Uploads (AUD-21):** statements, documents and WhatsApp accept only their fields, each once, one file, short text; extra parts are 400 `UPLOAD_001`. All bodies capped before routing (AOS-615).
- [x] **Gmail redirect (AUD-18):** authorize-url and connect accept only `APP_URL/connections/gmail/callback`.
- [x] Playwright: header checks, CSP without violations, injected inline handlers blocked, API headers, CSRF refused/accepted, sign-in state/PKCE and forged state refused.

## Design
- **CSP options:** 1) **nonce per response in `proxy.ts`** + dynamic rendering (chosen: the only way to keep scripts strict with Next's inline bootstrap scripts); 2) hashes of Next's inline scripts (they change per build and per page; brittle); 3) `'unsafe-inline'` (rejected by the task and by ASVS). Cost: pages are rendered per request (`force-dynamic`), fine for a single-user app. Styles keep `'unsafe-inline'` because charts set `style=` attributes; styles can't execute code.
- **CSRF options:** 1) **Fetch Metadata + Origin check, fail closed** (chosen: no token plumbing, works through the same-origin proxy, verified that Next forwards `Origin` and `Sec-Fetch-Site`); 2) double-submit token (needs JS-readable cookie and client changes everywhere); 3) Ktor's CSRF plugin (allows requests without Origin; we want fail closed). `SameSite=Strict` stays as the first layer.
- **Sign-in state options:** 1) **reuse the D-64 server-side state store with a new `LOGIN` purpose and a browser-binding cookie** (chosen: one audited mechanism; single use is one conditional update); 2) an HMAC-signed state in a cookie only (no server-side single use); 3) keep no state (owner-only limits impact, but ASVS V10 and RFC 9700 require it).
- **Lockout options:** 1) **per-client exponential backoff on refusals, cleared on the owner's success** (chosen); 2) a global lock (lets a stranger lock the owner out); 3) none (Google already blocks guessing, but the route still amplifies traffic to Google).
- **Client IP options:** 1) **distrust by default, explicit setting behind an appending edge** (chosen); 2) keep trusting the last hop (spoofable, proven); 3) a custom header set only by our edge (needs a secret between edge and API; revisit with AOS-616).

## Security (D-100 §4a)
- **Exposes:** one new public route, `GET /api/v1/auth/google/start` (allowlisted in the route inventory: it only issues a state and returns Google's URL; rate limited and lockout-guarded). New cookie `login_state` (HttpOnly, Strict, path `/api/v1/auth`, 10 min). Migration V60 (tentative) lets sign-in states have no user, enforced by a CHECK.
- **Abuse and what stops it:** forged sites posting with the owner's cookies → CSRF check; framing → `frame-ancestors`/XFO; injected markup → CSP; planted or replayed sign-in codes → state cookie + single-use state + PKCE; brute force or Google amplification → lockout; spoofed IPs → distrusted by default; oversized or odd uploads → form shape checks; leaked internals in errors → sanitised.
- **Tests:** unit (guard, limiter bound, sanitiser, JWT, origin), route (sign-in state, lockout, CSRF, headers, uploads, Gmail redirect), integration (V60 on Postgres), Playwright (`security.spec.ts`).

## Proposed decision D-94 — Browser and sign-in hardening (Type: Architecture)
- Web pages: per-response nonce CSP from `proxy.ts` (scripts: nonce + `strict-dynamic`, never `unsafe-inline`), `frame-ancestors 'none'`, and the standard hardening headers from `next.config`; API responses: `default-src 'none'` CSP, `no-store`, the same headers; no CORS.
- Cookie-authenticated mutations require `Sec-Fetch-Site: same-origin` or the app's exact `Origin`; neither → 403. `APP_URL` must be the exact browser origin.
- Google sign-in uses a server-side single-use state + PKCE (D-64 store, purpose `login`) bound to the browser by an HttpOnly cookie, identity scopes only.
- Refused sign-ins back off exponentially per client (5 free per 15 min, 1 min → 1 h).
- **Amends D-32:** the API trusts `X-Forwarded-For` only with `TRUST_FORWARDED_FOR=true`, which a deployment sets only behind an edge proxy that appends the real peer.
- JWTs: exactly HS256, `exp` required. Client errors never echo library text.

## Risks / notes
- **Owner action:** `APP_URL` must be exactly the origin used in the browser (e.g. not `localhost` when you open `127.0.0.1`); otherwise every change is refused as cross-site and Google sign-in fails. Behind Tailscale serve (AOS-616) set `TRUST_FORWARDED_FOR=true` only once it appends `X-Forwarded-For`.
- Pages are now rendered per request (needed for nonces).
- Sign-in now needs `GET /api/v1/auth/google/start`; any old bookmarked Google consent URL stops working (it has no state).
