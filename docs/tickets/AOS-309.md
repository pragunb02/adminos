## Description
Frame **M/Review** of `docs/design/console.md`: the pairs the accuracy engine wasn't sure about (possible duplicates, transfers between your accounts, refunds, reversals). Until they're answered the totals are provisional.

## Acceptance criteria
- [x] Tabs All / Duplicates / Transfers / Refunds (refunds + reversals) with counts; the tab is in the URL (`?kind=`), so back/forward/refresh restore it.
- [x] Each card shows both sides (merchant, signed amount, date, source, account, category), the reason and the score.
- [x] Answers are in plain language per kind (e.g. "Same payment" / "Different", "Yes, a transfer" / "No").
- [x] Undo instead of confirm (D-49): the card hides at once; the answer is sent after 5 s unless Undo is pressed. A second answer sends the first one immediately; leaving the page sends a pending one.
- [x] A refused answer is reported (`role=alert`) and the card returns; a load error can be retried.
- [x] Empty states: "All clear — your totals are final." / "Nothing to review in {tab}."
- [x] After an answer, suggestions, analytics and the feed are refreshed (totals and the Review badge change).

## Resolution
Done.
- **Web:**
  - `app/review/page.tsx` replaces the placeholder;
  - `UndoToast` keeps `onClose` in a ref so its 5 s timer runs once per message; Activity and Review key the toast by message so a new message restarts the timer.
- **Tests:**
  - Unit: 10 Review tests (fake timers for the Undo window). Web 283 tests, 98.49% lines / 95.85% branches.
  - Playwright `review.spec.ts`: tabs with back/forward/refresh, Undo sends nothing, send after 5 s then refresh, leave-page send, all clear, axe with cards and the Undo bar; on 3 browsers (15). Suite 217 passing + 4 deliberate skips.
- **Note:** the nav's Review badge reads the same endpoint under its own cache key (`["suggestions","count"]`), so /review makes two requests; an answer invalidates both through the `["suggestions"]` prefix. Sharing one entry is a small later optimisation, not needed now.
