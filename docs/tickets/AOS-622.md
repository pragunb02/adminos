## Description
CI on every PR (all four stacks), dependency, image and code scanning with explicit fail/report policies,
pinned base images and locked dependencies, hardened containers (non-root, read-only, no capabilities,
no-new-privileges, limits, healthchecks), network segmentation, Dependabot, and a merge script that can't
merge before every required check has reported. Full reference: [`docs/security/SUPPLY-CHAIN.md`](../security/SUPPLY-CHAIN.md).

## Why
D-91 layer 6 (supply chain and runtime) and the D-100 gate ("dependency scan green"). Until now nothing ran
on PRs except GitGuardian, base images floated on tags, the parser's transitive dependencies were unpinned,
and every container could reach Postgres and Redis.

## Design
- **Context:** GitGuardian only; four stacks (Kotlin/Gradle, Next/npm, Go ×2, Python); images on floating tags;
  `merge-pr.sh` judged "every listed check", so it could merge when only the fast GitGuardian check existed.
- **Options considered (dependency scanning):**
  1. **OSV-Scanner over lock files** + ecosystem-native tools where they add reachability (govulncheck) or
     production scoping (npm audit) (chosen): one policy across ecosystems, free, no API key.
  2. OWASP dependency-check: JVM-centric, slow, needs an NVD API key (a CI secret) for reliable updates.
  3. Dependabot alerts only: good signal but not a PR gate.
- **Options considered (Gradle integrity):** 1) **locking + `verification-metadata.xml` (sha256)** (chosen:
  reproducible and tamper-evident, also for plugins); 2) locking only (versions, not bytes); 3) nothing (status quo).
- **Options considered (image policy):** 1) **fail on any CRITICAL (fixed or not), report HIGH** (chosen; an unfixed
  critical needs a dated decision); 2) fail on fixed CRITICAL only (silently ships unfixed criticals); 3) fail on HIGH
  (blocks on 44 unfixable Debian findings today).
- **Options considered (segmentation):** 1) **three networks** (backend / edge / internal parser) (chosen);
  2) one default network (status quo: a parser or web compromise reaches the database).
- **Decision / patterns:** fail closed everywhere (scanner errors, missing required checks, unreadable lists,
  unscored advisories); explicit, dated exceptions; checks as scripts (run locally and in CI identically).
- **Extensibility:** a new service gets checked automatically (hardening + exposure checks iterate all stacks
  and profiles); a new language adds a lock file to `osv-scan.sh`, a Dependabot entry and a CodeQL matrix row;
  a new required check goes in `.github/required-checks.txt` and branch protection together.
- **Impact:** compose (hardening, networks, Redis volume), all Dockerfiles, API build (locks, verification),
  pdf-parser requirement layout (`*.in` → hash-locked `*.txt`), merge script. No app code or schema change.

## Security (threat review, ENGINEERING §4a)
- **Exposes:** nothing new at run time. CI runs PR code with a read-only token and no secrets.
- **Abuse and what stops it:**
  - malicious dependency or substituted artifact → hash verification (Gradle metadata, pip `--require-hashes`, `go mod verify`, npm lock integrity), CI install without lifecycle scripts;
  - known-vulnerable dependency or image → OSV / npm audit / govulncheck / Trivy gates, weekly re-scan, Dependabot;
  - compromised Action → SHA pins, least `permissions`, no secrets, no `pull_request_target`;
  - PR weakens its own gate → required list read from main; branch protection mirrors it;
  - merge before CI ran → missing required checks are waited for, then refused;
  - container breakout aids → non-root, no capabilities, no-new-privileges, read-only roots, no package manager at run time;
  - lateral movement from the parser or web app → network segmentation (smoke-tested: no route to Postgres/Redis; parser has no internet).
- **Tests that attack it:** hardening-check fixtures (each rule removed, root users, tag-only images, unpinned
  `FROM`, `USER` only in a builder stage); merge-script cases (required check never reported, list unreadable or
  empty, extra failed check); smoke test proves segmentation and read-only roots at run time.

  keeps going when one bill fails`) builds bills from `LocalDate.now()` in the JVM's zone (UTC on runners), while

## Proposed decision D-99 — Supply chain and runtime: scan everything, pin everything, run least-privileged
Type: Architecture / Security / Process · Tasks: AOS-622 · Builds on D-91, D-100, D-101
- **Every PR** runs CI (all stacks), Security (OSV-Scanner, npm audit, govulncheck, Trivy + hardened-stack smoke)
  and CodeQL; Security and CodeQL also weekly. All are **required checks** (`.github/required-checks.txt` = branch protection).
- **Policies:** dependencies fail at CVSS ≥ 7 or unscored; images fail on any CRITICAL or secret; HIGH is
  reported. Exceptions only with a reason and an expiry (`osv-scanner.toml`, `.trivyignore.yaml`).
- **Pinning:** images by digest; Gradle locked + SHA-256 verified; Python hash-locked (pip-tools); npm/Go lock
  files; Actions by SHA. Dependabot proposes every update weekly, grouped.
- **Runtime:** every container non-root, read-only root, all capabilities dropped, no-new-privileges, memory/CPU/PID
  limits, healthchecks; no package manager at run time; networks `backend` / `edge` / internal `parser`.
- **Merging:** `merge-pr.sh` (main's copy) waits for every required check, refuses on any non-success, and keeps D-101.
- **Rejected:** OWASP dependency-check (needs an NVD key secret, slow); failing on HIGH images (blocks on unfixable
  base-image findings); Dependabot alerts as the only gate.
