## Description
These issues were found while building AOS-509 (waste score) and while reading the detector:
- the category was always Other;
- subscriptions that stopped charging never ended;
- `merchantName!!`, and dates in UTC rather than the user's zone;
- **yearly plans could never be found** (a 90-day look-back);
- the next charge drifted ("+30 days");
- the subscription review routes called the repository directly (layer rule);
- the "cancel" endpoint claimed "cancellation draft queued" when nothing happened.

## Acceptance criteria
- [x] The look-back is 400 days: a yearly plan (two charges about a year apart) is found, and so is quarterly.
- [x] Dates are the user's own (`UserCalendar`).
- [x] The next charge is calendar-correct: a month after 11 Oct is 11 Nov, and month ends stay month ends.
- [x] **Category:**
  - it comes from the merchant catalogue's subcategory: streaming, music and TV → Entertainment; cloud → Cloud; fitness → Fitness; food delivery → Food; apps and courses → Productivity; news → News; gaming → Gaming;
  - otherwise from the charges' own category;
  - else Other.
  - A category the user (or an earlier run) set stays.
- [x] **Ending:** an active subscription with no charge for two cycles plus 7 days is marked cancelled, with `endedBy=detector` and `endedReason` and no next date. A new charge brings it back and clears the reason.
- [x] No `!!` in the detector.
- [x] `SubscriptionReviewService` holds the keep and cancel logic; routes only map HTTP. A malformed ID stays 400, and an unknown or someone else's subscription is 404.
- [x] **"How to cancel"** (`POST /subscriptions/{id}/cancel`) returns real steps and changes nothing:
  - when an active AutoPay mandate pays it, it says where to revoke it (the UPI app, the bank's e-mandates, or the card's standing instructions), then to cancel with the service;
  - otherwise it says to cancel in the service's settings or the App Store / Google Play, and that AdminOS marks it ended after two cycles without a charge.
  - The request is audited.
- [x] **Web:** the flagged card's "Cancel" became **"How to cancel"**, a dialog with the steps (Escape, Close and backdrop close it). The dead "cancellation draft" modal is gone.

## Design
- **Ending options:**
  1. **Mark cancelled with a reason, reversibly** (chosen).
  2. A new `ended` status: this needs an enum migration, and "cancelled" already means no longer charging.
  3. Delete the row: history would be lost.
- **Cancel options:**
  1. **Honest guidance** (chosen).
  2. An AI-drafted cancellation email (the legacy `cancellation_draft` idea): later, if wanted, after the evaluation harness exists (D-57).
- **Decision:** D-65.

## Risks / notes
- **Ending can be wrong:** a quiet period (a paused plan, a skipped month) can mark a subscription ended too early. The next charge brings it back. Thresholds are constants.
