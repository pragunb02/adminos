## Description
- Real-browser tests of every screen, as a user moves through them.
  - Navigation chains with the browser's back and forward (back → next → back → back → next), deep links and refresh, the route guard and session expiry.
  - Every action on each screen, keyboard-only use, and an accessibility scan (axe) per screen.
- Runs on desktop Chrome, an iPhone (WebKit) and an Android phone (Chrome).

## Modes
- **Mocked API:** the browser's `/api/*` calls are answered from the shared fixtures (`apps/web/test/fixtures.ts`), so every branch is reachable, including errors and empty states.
- **Full stack:** the real API (in-memory mode) behind the real Next proxy.
  - The test signs a session token with the test secret and sets the cookie. There is **no auth bypass in production code**.
  - Proves the cookie, proxy and API work together, e.g. a cash entry appears in the feed.
- All servers bind to 127.0.0.1 only.

## Acceptance criteria
- [x] Every screen: deep link + refresh keeps you there; heading and main content visible.
- [x] Navigation chains across tabs: back/back/forward/back land on the right page each time; on mobile and desktop.
- [x] Route guard: no session → /login; expired session (refresh fails) → /login.
- [x] Per-screen flows: cash quick-add (save, double tap = one entry, Escape, error), anomaly review (resolve → next → home; back), subscriptions tabs and actions, settings toggles and device tokens, statement import (real file upload), transactions filters and load more, onboarding steps, login and callback.
- [x] Keyboard-only: reach the nav, open cash quick-add, save, close with Escape.
- [x] axe: no serious or critical violations on any screen.
- [x] Full stack: a signed-in user adds cash and sees it in the feed; a bad token is rejected.
- [x] `npm run e2e` runs everything headless; an HTML report is produced.

## Resolution
Done.
- **Harness:**
  - `playwright.config.ts` with 4 projects: desktop Chrome, iPhone 15 (WebKit), Pixel 7 (Chrome), and full stack;
  - two servers, both on 127.0.0.1: the API in in-memory mode with a throwaway secret, and the production Next build;
  - `e2e/support/mock-api.ts` (answers `/api/v1` in the browser from the shared fixtures; an unmocked endpoint is a loud 501; calls are recorded);
  - `e2e/support/fixtures.ts` (`signedIn`, `api`, `mainNav`, `expectAccessible`);
  - `e2e/support/session.ts` (signs a real access token for the test API; no production bypass).
  - Scripts: `npm run e2e`, `npm run e2e:report`.
- **Specs (131 tests across 4 files):**
  - `navigation`:
    - deep link + refresh on all 7 screens;
    - tab chains with back/forward, including a new branch dropping the old forward history;
    - all tabs then all the way back;
    - same-tab click adds no history;
    - nav position per screen size;
    - every nav item reachable;
    - the guard for every page;
    - expired session → login; refreshed session stays;
    - log out.
  - `screens`:
    - cash quick-add: a double tap is saved once; error → retry; Escape and backdrop; back still works after;
    - anomaly review: home → review → back → forward → resolve → next → resolve → home; pick another; ← Back;
    - subscriptions tabs and Keep;
    - settings: toggle saves; device token shown once; revoke with confirm;
    - statement import: a real file upload, password asked, then the result, a link to transactions and back;
    - transactions: load more and filters; server errors retry by themselves; a client error with retry;
    - login → Google with this app's callback; failed sign-in → message;
    - onboarding: skip both → dashboard, and back doesn't return to onboarding.
  - `a11y`: axe WCAG 2.2 AA on 11 screens and states (no serious or critical issues); keyboard-only nav → cash add → Escape.
  - `full-stack`:
    - a signed-in user adds cash and sees it in the feed and in the month's analytics total;
    - one user's data is invisible to another;
    - a wrongly signed or expired token → 401 → login;
    - a 400 carries the API's message.
- **Found and fixed:**
  1. **Colour contrast below WCAG AA** on every screen (grey-400 text, green/orange text, the "+ Cash" button, the inactive subscription tab, the highlighted summary label). Moved to compliant shades.
  2. **Log out was off-screen on phones,** because 8 items didn't fit a 393–412px bottom bar. The bar now scrolls; there is a regression test that fails without the fix on iPhone. The redesign cuts it to ≤5 tabs (AOS-302).
- **Found, not fixed (outside this step):** **AOS-607**, `JwtService` keys HS256 with only the first 32 bytes of `JWT_SECRET` (`copyOf(32)`).
