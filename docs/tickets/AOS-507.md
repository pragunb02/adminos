## Description
A private vault for the documents life admin needs: PAN, Aadhaar, passport, Form 16, insurance policies, vehicle papers and warranties.
- Each file is encrypted inside AdminOS with its own key before it goes to Cloudflare R2 (or any S3-compatible store).
- Files are downloaded only through the API, after sign-in, and only by their owner.
- Expiring documents get reminders.

## Acceptance criteria
- [x] **Upload** (`POST /api/v1/documents`, multipart): PDF, PNG, JPEG, WebP or HEIC (iPhone photos), up to 20 MB.
  - The file type is recognised from the bytes, never from the name or the browser's claim.
  - A category is required; the title is optional (it defaults to the file name); an expiry date and notes are optional.
  - Errors: empty → 400 `DOC_007`, unsupported → 415 `DOC_002`, too large → 413 `FILE_TOO_LARGE`, no file → 400 `DOC_006`.
- [x] **Envelope encryption (JDK crypto):**
  - each file gets a fresh 256-bit key and AES-256-GCM, with the document ID as associated data;
  - that key is wrapped with the app key (`TokenEncryptor`, context `document:<id>`);
  - tampered bytes, another document's ID, a wrong key or a broken format are refused;
  - a SHA-256 checksum is checked on every download.
- [x] **Storage only ever holds ciphertext,** under `documents/<id>` (no name or user detail).
  - **Upload order:** the file is written first, the row second. If the row fails, the file is removed again.
  - **Delete order:** the file goes first, the row second. If storage fails, the row stays.
- [x] **Only the owner** can list, get, download, edit or delete a document. Anyone else gets 404, not 403, so IDs reveal nothing. The API never returns the storage key, the wrapped key or the checksum.
- [x] **Download** (`GET /documents/{id}/file`): the decrypted file as an attachment, with a safe name (RFC 5987), `no-store` and `nosniff`.
- [x] **List** with category filter and search (title, notes, file name). **Edit** title, category, expiry and notes (and clear them); a new expiry resets its reminders.
- [x] **Storage set-up:**
  - **Configured:** S3/R2 via `DOCS_S3_*`, validated at start-up (https only, except a local test store; valid bucket name; required keys; the secret never printed).
  - **Dev mode without it:** memory only, logged loudly.
  - **Database mode without it:** refused with 503 `DOC_005`, never stored somewhere unsafe.
- [x] **Storage failures** → 503 `DOC_003`. A missing or damaged stored file → 502 `DOC_004`.
- [x] **Expiry reminders** (`document-expiry`, daily at 09:30): 30, 7 and 1 days before, once each per expiry date, on the user's own date.
- [x] **Web `/documents`** (More → Documents):
  - upload form, with a 20 MB check before sending and explained server refusals;
  - list with kind, type, size and expiry ("Expires in 25 days", "Expired");
  - Download;
  - inline Edit;
  - Delete with Undo, deferred 5 s (D-49): a second delete sends the first, and leaving the page sends it;
  - category in the URL (pushed) and search in the URL (replaced, D-47);
  - axe-clean.

## Design
- **Storage options (asked Pragun):**
  1. self-hosted open source (Garage, SeaweedFS, MinIO);
  2. free cloud tiers (Cloudflare R2, Backblaze B2, Oracle);
  3. both.
- **Pragun chose Cloudflare R2.** It speaks the S3 API, so one adapter covers R2 and any other store.
- **Encryption options:**
  1. **Envelope encryption in the app** (chosen): the provider never sees content, and a key per file limits the blast radius.
  2. R2 server-side encryption only: Cloudflare could read the files.
- **Decision:** D-60 (it extends D-37). **Patterns:**
  - ports (`DocumentStorage`, `DocumentSealer`) with adapters (S3/R2, in-memory for dev, unconfigured);
  - Null Object only in dev mode, logged;
  - the deferred-delete Undo shared with Review.
- **Extensibility:**
  - another S3 provider is configuration only;
  - another category is one enum value;
  - OCR or tagging later could read the decrypted bytes in the service.
- **Impact:**
  - **API:** `domain/documents/*`, `infrastructure/documents/*` (sealer, S3, in-memory, unconfigured), V23 `documents`, `DocumentStorageConfig`, AWS SDK v2 S3 with the URL-connection HTTP client (no Netty/Apache).
  - **Error handling:** the global handler now turns an over-limit multipart upload into a 413.
  - **Web:** `/documents`, `uploadData`, a More link, types, fixtures and e2e mocks.
  - **Ops:** compose and `.env.example` (R2 steps).

- **Manual check (Pragun):**
  1. Create an R2 bucket with public access off.
  2. Create an API token with Object Read & Write for that bucket only.
  3. Set `DOCS_S3_*` in `.env`.
  4. Upload a PDF on /documents, download it, and confirm the object in R2 is unreadable.

## Risks / notes
- **Found while testing, and fixed:** an upload over the multipart limit failed with 500 instead of 413. Ktor's parser raises the error in its own coroutine, so routes can't catch it; the global handler now maps it. This also fixes the same latent bug in statement import.
- **Auth failures:** S3Mock doesn't check credentials, so a wrong-credentials failure is covered by the R2 manual check instead.
- **Key loss:** files are as safe as `TOKEN_ENCRYPTION_KEY`. Losing it makes the vault unreadable. Back it up (noted in `.env.example` alongside the other keys).
- **Later work:** no OCR or full-text search inside files yet, and no sharing.
