## Description
`ruleSummary` in `apps/web/src/lib/leaks.ts` (AOS-902) describes a lens from its brands, categories, subcategories and keywords. AOS-912 (PR #138) adds a `paymentMethods` rule and makes the Pay later lens `paymentMethods: ["pay_later"]` only, and `GET /coach/lenses` lists `paymentMethods`. The web didn't know the field, so the Pay later card read "Counts only the merchants you add". Reported in #138's description.

## Why
The card must say honestly what a lens counts (D-81: lenses are data, and the page explains them).

## Scope
- **In:** `LensDefinition.paymentMethods` (optional, so an API without AOS-912 still works); `ruleSummary` says "purchases paid with pay later" (several methods joined with "or", ahead of the other rules); the fixtures match #138's lens file; Vitest; a Playwright spec (written, not run).
- **Out:** the API (AOS-912); any other copy on the page.

## Acceptance criteria
- [x] A lens with `paymentMethods: ["pay_later"]` and no other rule reads "Counts purchases paid with pay later.", not "only the merchants you add".
- [x] Known methods read as words (UPI, credit card, debit card, netbanking, cash, wallet, pay later); an unknown one reads with spaces for underscores; inherited object keys (`constructor`, `__proto__`) aren't looked up as labels.
- [x] A missing or empty `paymentMethods` adds nothing (an API without AOS-912 renders as before).
- [x] A hostile method name renders as text, never as HTML.
- [x] Playwright: the Pay later card in a real browser, and the hostile-name attack.

## Design
- **Context:** `ruleSummary` is a pure helper, used only by `LensCard`'s editor.
- **Options considered:** 1) one more clause in `ruleSummary`, with a small word map for the API's lower-case method names; 2) the API sends a ready-made sentence. Option 2 moves copy into the API and would need a contract change; rejected.
- **Decision:** option 1. The field is optional, so the web can merge before or after #138.
- **Impact:** web only (`lib/leaks.ts`, fixtures, tests). No API, contract or schema change.

## Implementation plan
1. Optional `paymentMethods` on `LensDefinition`; the clause in `ruleSummary`.
2. Fixtures as in #138's `lenses.json` (Pay later = `paymentMethods: ["pay_later"]`, description "Purchases paid with buy now, pay later").
3. Vitest (`leaks.test.ts`, `leaks/page.test.tsx`), Playwright (`e2e/leaks.spec.ts`).

## Security (§4a)
- **Exposure:** none new. No route, input, storage, dependency or outbound call. One more read-only field from the authenticated `GET /api/v1/coach/lenses` is shown as text.
- **Abuse:** a method name is server data (from the lens file, validated on load by AOS-912), but it is treated as untrusted anyway: React renders it as a text node, and the word map is a `Map`, so a name like `__proto__` or `constructor` can't pull an inherited value. Tests: a hostile `<img onerror>` name renders as text (Vitest and Playwright); inherited keys read as words.
- **Secrets / personal data:** none; fixtures are synthetic.
