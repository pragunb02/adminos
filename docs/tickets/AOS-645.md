## Description
Two items Pragun raised:
- **No SECURITY.md:** GitHub's draft template (on branch `pragunb02-patch-1`) lists made-up supported versions. The project has no releases, so the real policy is "latest `main` only", with reports sent privately through GitHub's private vulnerability reporting.
- **Code scanning alert #1 (CodeQL `js/regex/missing-regexp-anchor`, high)** in `apps/web/e2e/security.spec.ts:285`: the sign-in test checked the redirect with an unanchored `/accounts\.google\.com/`, so a URL like `https://evil.example/?accounts.google.com` would also pass. `screens.spec.ts:154` had the same pattern.

## Acceptance criteria
- [x] `SECURITY.md` states the scope (personal, single-user, no released versions), how to report privately, and what to expect.
- [x] Both e2e checks are anchored to `^https://accounts.google.com/`, and the sign-in test also asserts the exact host.

## Security
Test-only: the product's redirect was always to Google, but a weak assertion could have hidden a regression that sent sign-in to another host.

## Activity log
- 2026-10-18 — Claude (integration engineer): written and fixed.

## Resolution
`SECURITY.md` added. `e2e/security.spec.ts` and `e2e/screens.spec.ts` anchor the Google URL, and the security spec checks the host. This replaces the `pragunb02-patch-1` template draft.
