## Description
Originally "fix the API → worker payload contract". It was re-scoped once Pragun chose option A (D-34): process intake events in a Kotlin pipeline inside the API, and retire the Go SMS path. This removes the broken payload contract for SMS entirely.

## Design (approved by Pragun)
`ingest_events (pending)` → `IngestProcessor` (claims with `FOR UPDATE SKIP LOCKED`) → `IngestPipeline` (Chain of Responsibility: ToTransaction → NormalizeMerchant → Categorize) → `IngestOutcomeWriter` (transaction + status in one DB transaction).

## Acceptance criteria
- [x] Pending events become categorised transactions linked by `ingest_event_id` (exactly once: unique constraint + idempotent writer)
- [x] Concurrent processors never claim the same event; abandoned claims retried after 5 min
- [x] A failing event is marked failed with a reason (no raw text) and the batch continues; dropped → ignored with reason
- [x] Runs promptly after each ingest (`wake`) plus a 5 s sweep; starts with the app
- [x] `/ingest/sms` is an adapter onto the intake (fingerprint = `sourceRef`, so resends are duplicates)
- [x] Go SMS worker retired (handler, tests, registration, compose service)

## Resolution
- **Migrations:** V10 (enum values) + V11 (`claimed_at`, `transactions.ingest_event_id` unique).
  - Split because Postgres can't use a new enum value in the transaction that adds it.
  - **The integration tests caught this.** Shipping it would have stopped the API from starting.
- **Pipeline:** `IngestStep`, `IngestPipeline`, `ToTransactionStep`, `NormalizeMerchantStep`, `CategorizeStep`.
- **`MerchantNormalizer`** is deterministic: whole-word matching, longest alias wins, falls back to the UPI VPA handle. It fixes "COCA COLA" → Ola and "UBER EATS" → Uber from the Go version.
- **`IngestProcessor`, `RepositoryOutcomeWriter`; claim/finish** in the in-memory and Exposed repositories.
- **SMS:**
  - `SmsRecordAdapter` (dates: ISO with offset, local time or date → IST).
  - `SmsRecord.direction` (default debit).
  - Sync session is `completed` with accepted/duplicate counts; the 3 tests asserting the old `queued` behaviour were updated.
- **Go:** `sms_handler.go` and its tests removed; the `sms` worker type is gone; `sms-worker` removed from compose. `normalizer`/`categorizer` are kept for Gmail/PDF until AOS-401/202.
- **Tests:**
  - `MerchantNormalizerTest` (5)
  - `IngestProcessorTest` (7: categorised transaction, credits, exactly-once, failure isolation, drop, stale reclaim, live wake loop)
  - `IngestionServiceTest` +1 (SMS resend → duplicate)
  - `IngestPipelineIntegrationTest` (4: end-to-end on Postgres, 4 concurrent claimers disjoint, atomic+idempotent outcome, DB rejects a 2nd transaction per event)
- **Totals:**
  - Unit **192/192**, integration **40/40**.
  - Go build/vet (+integration tag)/test ✅.
  - Live: the API applies 11 migrations and starts the processor.
- **Noted:** 7 existing Go files aren't `gofmt`-clean (pre-existing → AOS-007).
- Actual 2.5h vs ETA 4h.
