## Problem
The same ₹249 payment arrives as an SMS, a statement row and maybe an email. Each source has its own id, so without this it's counted 2–3 times.

## Research (approved design, D-38)
| Tool | Approach | What we took |
|---|---|---|
| **GnuCash** | Points score, three bands (auto ≥6, ask, new ≤3) | Scoring + bands |
| **Actual Budget** | Import-id pass, then same amount within ±7 days, closest wins, 1:1, fill blanks only | Reference first, 7-day limit, 1:1, enrich blanks |
| **YNAB** | Same amount ±10 days; `amount:date:occurrence` ids | Occurrence ids (already in AOS-202) |
| **beangulp** | 2-day window, 5% tolerance | Asymmetric windows; fuzzy amounts never auto |
| **Plaid** | Pending → posted can change amount | Exact amount for auto-merge |
| **RBI** | Failed payments reversed T+1…T+5 | Reversals are not duplicates (AOS-209) |

## Rules (`TransactionMatcher`, `dedup-v1`)
- **Hard rules** (otherwise never the same payment):
  - same user, direction, exact amount and currency;
  - **different source**, and that source not already merged into the candidate (1:1);
  - no conflicting account last 4 or reference;
  - inside the window; not a rejected pair.
- **Pass 1:** the same UPI/IMPS reference (RRN) is decisive.
- **Pass 2 score:** amount +4 · same account +3 · same UPI ID +5 · same day +3 / in window +1 · merchant similarity 0–2.
- **Bands:** ≥8 auto-merge · 5–7 suggest · <5 separate. **Ambiguity guard:** the best must beat the runner-up by ≥3, else suggest. **Manual entries** are only ever suggested.
- **Windows:**
  - statement vs SMS/email: UPI/IMPS/unknown ±1 day; card −1…+3 days (posting lag); NEFT ±2 days.
  - SMS vs email: ±10 min. Manual: ±2 days.
  - Hard limit: 7 days.

## Implementation
- **V13:** `payment_ref` on events and transactions (+ indexes); `transaction_links` (merged/suggested/rejected, score, reason, rules version).
- **Reference extraction:**
  - SMS (`Ref`, `Refno`, `UPI:`, `RRN` + 12 digits).
  - Statements: the reference column, or a 12-digit number in the narration.
  - Statement **payment method** inferred from the narration (UPI/POS/ATM/NEFT…). `paymentRef` added to `/ingest/events`.
- **Pipeline:** `CrossSourceDedupStep`, plus `StepResult.Merge`, `PipelineOutcome.Merged` and `Created(suggestion)`.
  - `enrich()` fills blanks only (never category/amount/user edits).
  - The writer links the event and updates the target atomically.
- **`RepositoryMatchCandidates`** (indexed query + merged sources).
- **Review API:**
  - `GET /api/v1/transactions/duplicates`
  - `POST …/{id}/confirm` (fill blanks, delete the duplicate, keep the link, atomic)
  - `POST …/{id}/reject` (remembered)
  - Owner-only.
- **Also fixed:** `ExposedTransactionRepository.update` didn't save merchantRaw/account/payment method/VPA/metadata. Any update silently dropped them.
