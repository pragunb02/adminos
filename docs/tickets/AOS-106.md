## Description
Ktor bearer auth: fall back to the `access_token` cookie when there's no Authorization header.

## Why
The web app sends only the HttpOnly cookie, so every call returns 401.

## Acceptance criteria
- [x] Cookie-only request is authenticated
- [x] Header still works; an explicit (bad) header does not fall back to the cookie
- [x] `AuthenticationTest` (6 cases) against production `configureAuthentication`

## Implementation plan
1. authHeader override in Authentication.kt
2. Route test

## Verification
- `./gradlew test`

## Activity log
- 2026-10-16 — Claude: ticket created (AOS-004).
- 2026-10-16 — Claude: started. Pragun chose snake_case for AOS-107. Found that IngestionRoutesTest duplicates the auth config instead of using production `configureAuthentication`.

## Resolution
- The bearer provider's `authHeader {}` reads `Authorization` first, then the `access_token` cookie (blank values ignored).
- `ACCESS_TOKEN_COOKIE` constant shared by login, refresh and logout.
- CSRF: the cookie is `HttpOnly` + `SameSite=Strict`; localhost:3000 and localhost:8080 are the same site.
- `IngestionRoutesTest` now uses production `configureAuthentication` instead of a copy.
- Unit 148/148. Actual 0.5h vs ETA 1h.
