## Description
- Clean, consistent merchant names for the console and for remembered rules (D-41):
  - one merchant catalogue, about 100 Indian brands incl. legal entity names, shared by the normalizer and the categorizer;
  - payee names pulled out of bank narration structure.

## Why
- **Raw narrations leaked into the console:** `UPI-RAMU CHAIWALA-ramu@okicici-…` showed as "Upi-ramu Chaiwala-…".
- Merchant-name rules (AOS-210) depend on stable names.
- Two brand lists (normalizer, categorizer) could drift apart.

## Scope
- **In:**
  - `resources/merchants/catalogue.json` (104 brands), validated on load;
  - `NarrationCleaner`;
  - normalizer order: brand → cleaned name → UPI handle;
  - the categorizer reads the catalogue.
- **Out:** a user-editable merchant list (AOS-3xx); learning new brands from data.

## Acceptance criteria
- [x] Legal names map to brands: Bundl → Swiggy, ANI Technologies → Ola, Bigtree → BookMyShow, Interglobe → IndiGo.
- [x] Gateway prefixes are stripped: `PAYU*NYKAA` → Nykaa, `RAZ*SHARMA SWEETS` → Sharma Sweets.
- [x] HDFC and SBI UPI formats and POS card narrations give the payee name; inner words are kept.
- [x] The UPI handle is the name when the narration has none.
- [x] Whole-word matching still holds: Motorola is not Ola, JioMart is not Jio.
- [x] A bad catalogue fails at startup: duplicate alias, unknown category, an alias under 3 characters.
- [x] The categorizer and normalizer use the same catalogue.

## Design (approved by Pragun 2026-10-16, "ok")
- Data, not code (Open/Closed): adding a brand is a JSON edit.
- Matching form: upper case, punctuation → space.
- Cleaner:
  - split on `- / | :`;
  - drop UPI IDs;
  - trim channel words, bank codes, IFSC codes, references and masked cards from the ends of each part;
  - strip legal suffixes and a trailing city.
