## Description
Store the refresh token in an HttpOnly cookie; the web app retries once via /auth/refresh on a 401; add a logout button (current session only).

## Why
Sessions currently die after 1h and there's no logout.

## Acceptance criteria
- [x] Still logged in after the access-token TTL (API tested; browser flow verified in AOS-112)
- [x] Logout clears both cookies and revokes only this device's session

## Implementation plan

2. Web fetch wrapper retry
3. Logout UI

## Resolution
- **`AuthCookies`** is the single place for session cookies (replaced 3 copy-pasted blocks):
  - `access_token`: the JWT, 1h. The **cookie** lives as long as the session (30 days), so the web page guard doesn't bounce you every hour.
  - `refresh_token`: HttpOnly, scoped to `Path=/api/v1/auth`.
  - Both are SameSite=Strict, and Secure off localhost.
- **Tokens removed from all response bodies** (login and refresh), so they're never readable by JavaScript or XSS. Non-browser clients get a token flow later (AOS-604).
- **`POST /auth/refresh`:** reads the cookie and sets a new access cookie. Expired, revoked or unknown sessions return 401 and clear the cookies.
- **`POST /auth/logout`** is now **public** (so it works after the JWT has expired):
  - Revokes **only this device's** session; before, it revoked all of them.
  - Clears both cookies and writes an audit entry.
- **Web `api.ts`:**
  - On a 401 it refreshes **once** (concurrent requests share the refresh) and retries; if that fails it goes to `/login`.
  - `api.logout()`; a **Log out** button in the nav.
- **Tests:** `AuthSessionRoutesTest` (6). Unit **165/165**. Web typecheck/lint/build ✅.
- **Not automatically tested:** the web client logic (no web test framework yet). Browser behaviour gets checked in AOS-112.
- **Follow-up:** AOS-121, refresh-token rotation with reuse detection.
