## Description
Think like an attacker, then fix. Write the threat model (assets, attackers, trust boundaries, data flows, STRIDE
per boundary) and attack every route and surface against OWASP ASVS 5.0 Level 2 and the WSTG. Each finding gets a
severity with CVSS-style reasoning, a proof and a fix. Critical and high findings are fixed here or in linked tasks;
medium and low ones become ticket rows.

## Why

## Design
- **Context:** single-owner app, nothing deployed yet; the network layer (AOS-616) is still open; many controls exist but were never attacked as a whole.
- **Options considered:**
  1. **Code-led audit with targeted live probes** (chosen): read every route and plugin against ASVS L2 / WSTG, then prove each suspicion on a loopback instance (raw sockets, curl, a production Next build) and turn proofs into tests.
  2. Automated scanning first (ZAP baseline, dependency scanners only): fast, but misses logic flaws (owner-only, IDOR, token lifetimes, proxy header trust) and gives no tests. Kept for AOS-623.
  3. External pen-test: independent, but nothing deployed to test and no budget; revisit before any exposure beyond the private network.
- **Severity:** CVSS 3.1 base vector for the generic flaw, then an environmental note for how reachable it is here (single user, loopback binds today, private network planned). The higher of "base" and "here" decides when it must be fixed; the table shows both when they differ.
- **Fix placement:** a finding is fixed where its control lives: AUD-01/02 here; header, CSRF, OAuth state, JWT and rate-limit work in AOS-618; session work in AOS-620; MFA in AOS-617; route/IDOR tests in AOS-619.

## Security (D-100 §4a)
- **Exposes:** nothing new. Adds a pre-routing body-size gate (a new 411/413 response on every route) and removes an unused library.
- **Abuse and what stops it:** a stranger sending huge or chunked bodies to an unauthenticated route → refused from the headers alone, before auth, routing or decoding.
- **Tests:** unit (limit selection per path and method, hostile sizes), route (over-limit body never reaches the handler), real-server raw-socket tests (declared 100 MB with no body → immediate 413; chunked → 411). Route inventory and Playwright specs come in AOS-619.
- **Checks:** no secrets in tests (sizes and junk bytes only); no new listener; dependency change reduces the graph; scans green.

## Proposed decision D-92 — Threat model and audit method (Type: Process / Architecture)
- `docs/security/THREAT-MODEL.md` is the reference for every security-relevant change; the security gate (D-100) reviews a change against its attackers T1–T6 and boundaries TB1–TB11.
- Audits use ASVS 5.0 L2 + WSTG, a CVSS 3.1 base score plus an environmental note, and a proof per finding (a failing-before test where possible). Findings are `AUD-nn` rows in a dated audit file; open ones stay general in the public repo until fixed.
- **Every request body is size-capped before routing:** `Content-Length` required, 1 MiB default, larger limits only for explicitly listed upload paths.
- **Dependency advisories are fixed on discovery** even when the environmental risk is low; transitive libraries are pinned with a BOM when needed, and unused dependencies are removed.
- Rejected: scanner-only audits; relying on the order "auth before body" for safety.
