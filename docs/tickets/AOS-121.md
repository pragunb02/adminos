## Description
- On every `/auth/refresh`, issue a new refresh token, store its hash on the session, and invalidate the old one.
- If an old (rotated) token is used again, revoke the whole session family; that signals theft.

## Why
OWASP recommends rotation. Today a stolen refresh cookie stays valid for 30 days.

## Acceptance criteria
- [x] New refresh cookie on each refresh (`SessionSecurityTest`)
- [x] Reusing an old token revokes the session (`SessionSecurityTest`, `SessionRotationIntegrationTest`)

## Resolution
Done in [AOS-620](AOS-620.md): rotation on every refresh, rotated hashes kept per session (V61), reuse after a 30 s grace revokes the session and alerts the owner.
