## Problem (found by AOS-312 tests)
- `AuthService.kt:39-58,82-98`: deactivated or deleted users can log in and refresh.
- `GoogleOAuthClient.kt:48-52`: `code` and `redirect_uri` aren't URL-encoded, so `+ & %` corrupt the form or inject fields.
- `AuthCookies.kt:23`: any `APP_URL` starting with `http://localhost` (e.g. `http://localhost.example.in`) drops `Secure`.
- Revoking someone else's session returns 200 and audits a revoke that never happened.

## Fix
- Check `isActive && deletedAt == null` on login and refresh (→ 403 USER_INACTIVE; revoke the refresh token).
- Build the form with `URLEncoder`.
- Treat it as local only when the host is exactly `localhost`, `127.0.0.1` or `::1`.
- Revoking a session that isn't yours → 404, with no audit entry.
