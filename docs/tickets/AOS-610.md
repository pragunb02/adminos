## Problem (found by AOS-312 tests)
- `AuthService.kt:39-58,82-98`: deactivated or deleted users can log in and refresh.
- `GoogleOAuthClient.kt:48-52`: `code` and `redirect_uri` aren't URL-encoded, so `+ & %` corrupt the form or inject fields.
- `AuthCookies.kt:23`: any `APP_URL` starting with `http://localhost` (e.g. `http://localhost.example.in`) drops `Secure`.
- Revoking someone else's session returns 200 and audits a revoke that never happened.

## Fix
- Check `isActive && deletedAt == null` on login and refresh (→ 403 USER_INACTIVE; revoke the refresh token).
- Build the form with `URLEncoder`.
- Treat it as local only when the host is exactly `localhost`, `127.0.0.1` or `::1`.
- Revoking a session that isn't yours → 404, with no audit entry.

## Resolution
Done.
- **Inactive users:** `User.canSignIn()` (active and not deleted) is checked on Google login → **403 USER_002**. On refresh it gives 403 USER_002, the cookies are cleared **and the session is revoked**.
  - An access token already issued stays valid until it expires (≤1h).
- **OAuth form:** the token request body is built with `formEncode` (`URLEncoder` for every name and value).
- **Cookies:** `Secure` is dropped only for `http://` with a host exactly `localhost`, `127.0.0.1` or `::1` (`isLocalDevUrl`).
- **Session revoke:** `revokeSession` returns whether it revoked anything. Someone else's (or an unknown) session → **404 AUTH_006, nothing audited**. A malformed id is still 400.
- **Tests:**
  - the 4 former bug tests now pass (refresh + login of an inactive user, form encoding, `Secure` for `localhost.example.in`);
  - added: an inactive user's refresh clears cookies and revokes the session; revoking another user's session → 404 with no audit; `isLocalDevUrl` (11 URLs); `formEncode`; `canSignIn`.
  - Unit 1,053 / integration 85 green (11 + 1 bug tests remain for AOS-611…613); `koverVerify` passes.
