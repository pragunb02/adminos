## Description
A calm "Ask your money" page at `/ask`, reached from Home and More. It has:
- a question box and tappable suggestions (English and Hinglish);
- the answer, with how it was made (worded by AI and checked, or straight from the data);
- "How I got this": each tool, its dates, its numbers, and a link to the same payments in Activity;
- thumbs up/down, which stores the masked question and the plan for the eval set.

The feedback needs a small API: `POST /api/v1/ask/feedback {askId, helpful}` and the `ask_feedback` table (V80, tentative), encrypted at rest.

## Why
Story AOS-S7.3 and research §7: answers in seconds on the phone. Feedback grows the eval set from real (masked) questions instead of guesses.

## Design
- **Context:**
  - D-49: Home answers one question, with exactly 5 tabs on phones. D-47: Vitest and MSW, then Playwright.
  - Text from the server can carry hostile merchant names (AOS-712 seed).
- **Options considered:**
  1. **A page at `/ask`, linked from Home and More** (chosen). It is deep-linkable, back/forward and refresh work, there is no focus trap to get wrong, and it reads well on a phone. The question is **not** put in the URL: it can hold personal details and would sit in history.
  2. **A bottom sheet on Home** (as the research sketched). Rejected for now: it needs a focus trap and Escape/back handling, an answer can't be linked to, and Home stays a single-purpose screen (D-49). A sheet can open the same component later.
  3. **A 6th tab.** Rejected: D-49 fixes 5.
- **Feedback refers to an answer by id.** The browser sends only `{askId, helpful}`. The server keeps the masked question and the plan for an hour (`RecentAsks`) and stores them only when the user votes. A client can't write arbitrary eval rows, and nothing is stored for unrated questions.
- **Links** go to Activity (`/transactions?from&to&category&q`), the console screen that shows the same payments for any dates, built with `URLSearchParams` (a merchant name can't add parameters).
- **Patterns:**
  - TanStack Query: a query for the status, mutations for the question and the vote;
  - presentational helpers in `lib/ask.ts`, tested on their own.
- **Impact:**
  - a new route `POST /api/v1/ask/feedback`;
  - a new table `ask_feedback` (V80, tentative);
  - Activity link format reused as is.

## Security (threat review, ENGINEERING §4a, D-100)
- **What this exposes:**
  - a page `/ask` behind the route guard;
  - `POST /api/v1/ask/feedback` behind `authenticate`;
  - stored data: `ask_feedback` rows. The masked question and the plan are one AES-256-GCM payload (`TokenEncryptor`, bound to `ask_feedback:<askId>:payload`). Plain columns hold only the user, the vote, the source, the prompt version and the time. Rows cascade with the user;
  - no new dependency, secret or listener.
- **How it could be abused, and what stops it:**
  - **Signed out, or a session the API refuses:** the route guard sends you to login, and the API returns 401 on every Ask route (`ask.spec.ts`, `AskRoutesTest`).
  - **Rating someone else's answer or poisoning the eval set:** an `askId` is a random UUID tied to its user in `RecentAsks` for an hour. Another user's or an unknown id gets 404, a malformed one 400. The body can't carry a question or a plan.
  - **XSS through the answer, the question echo or merchant names:** all are React text nodes. `ask.spec.ts` and `page.test.tsx` feed `<script>` and `<img onerror>` text and check that nothing runs and no element is created. Links are built with `URLSearchParams`, so a name can't inject parameters or a `javascript:` URL (hrefs always start with `/transactions?`).
  - **Personal data at rest:** the stored question is masked (`PiiMasker`) **and** encrypted, and a payload copied to another row fails to decrypt (`AskFeedbackIntegrationTest`). The schema refuses a plaintext payload (`CHECK payload LIKE 'v2:%'`) and unknown sources.
  - **Personal data in the URL, storage or logs:** the question isn't in the URL or Web Storage (`ask.spec.ts`). The API logs ids, counts and codes only.
  - **Memory growth from many asks:** `RecentAsks` keeps at most 20 per user for 1 hour, and the per-user quota (AOS-710) bounds the rate.
  - **CSRF on the vote:** a SameSite=Strict cookie and a JSON body. `SameOriginMutations` comes with AOS-704 (integration note in AOS-710).
- **Tests that attack it:**
  - `AskFeedbackTest`, `AskRoutesTest` (feedback);
  - `AskFeedbackIntegrationTest`;
  - `page.test.tsx` (hostile text rendered as text);
  - `ask.test.ts` (encoded links);
  - `e2e/ask.spec.ts` "attacks": signed out, refused session, hostile text, nothing in storage or the URL;
  - the `navigation.spec.ts` route-guard row for `/ask`.

## Proposed decision D-110 (for DECISIONS.md)

- **What it shows:**
  - the answer, labelled as worded by AI (numbers checked) or straight from the data, with the notice on a templated answer;
