## Description
End-of-day prices for Indian mutual funds:
- a daily job downloads AMFI's whole-market `NAVAll.txt`, keeps the NAVs of instruments we know (by ISIN, else scheme code) and stores them per (instrument, date, source);
- each imported statement's valuation NAV is kept as a price of its date (source `statement`), so holdings have a value before the first AMFI run;
- a valuation uses the **last price on or before** the date; past the instrument's limit (4 days for a mutual fund) it is **labelled stale**, never zeroed or dropped; an instrument with no price at all is left out (the caller values it at cost and says so).

## Why
D-79 and WEALTH-RESEARCH §2: free official bulk files first, so a provider never learns what the owner holds; staleness labelled honestly.

## Design
- **Context:** instruments come from CAS imports (AOS-805) with an ISIN and often no AMFI code (casparser's database can be older than a fund).
- **Options considered:**
  1. **Source:** (a) **AMFI's whole-market file**; (b) a per-scheme API (e.g. a community MF API). (b) tells a third party exactly which schemes are held and has no published terms; (a) is official and reveals nothing. Chosen (a).
  2. **What to store:** (a) every row of the file daily (~14k rows a day); (b) **only instruments we know**. (b): the file is public and can be re-fetched; storing all would grow ~5M rows a year for no use. History backfill for snapshots (AOS-816) can use AMFI's history report later.
  3. **Matching:** (a) scheme code; (b) **ISIN first, then scheme code**. ISIN identifies the exact plan/option; the code is shared by an IDCW scheme's payout and reinvestment ISINs (same NAV), and many instruments have no code.
  4. **A statement's NAV:** (a) ignore it; (b) **store it as a lower-priority price of its date**. (b) values a fresh import immediately; AMFI replaces it for the same date.
- **Decision:** proposed **D-162** below. **Patterns:** Port/Adapter (`NavFileSource`), scheduled job (D-50), repository contract.
- **Extensibility:** another source is a `PriceSource` value plus an adapter and a job; staleness limits are per instrument kind in `Staleness`.
- **Impact:** V72; one more scheduled job (job count 12); `CasImportService` records statement NAVs; `InstrumentRepository.mutualFunds()` replaces `withAmfiCode()`.

## Security (D-100, docs/ENGINEERING.md §4a)
- **Exposes:** one outbound HTTPS GET a day to `portal.amfiindia.com` (public file); no new routes; a new table of public prices; a scheduled job.
- **Abuse and what stops it:**
  - *Privacy (what leaves):* the request carries no cookies, credentials or holdings; the file is the whole market, so AMFI learns nothing about the owner's schemes (D-79).
  - *Hostile or broken file (MITM is prevented by HTTPS; a compromised or changed source):* header check stops on a format change; each value is validated (code digits, NAV decimal > 0 with ≤ 10 places, ISIN pattern, strict date); a row cap; the body is capped at 16 MB before decoding; nothing is executed or rendered.
  - *SSRF / redirection:* the URL is a constant, https only (a non-loopback `http` URL is refused), redirects are not followed (test).
  - *Availability:* a failed fetch throws, the job is retried per D-50, and valuations fall back to the last stored price, labelled stale.
- **Data at rest:** public prices, not sensitive. **Secrets:** none. **Dependencies:** none (JDK HTTP client).

## Proposed decision D-162 (for the integrator)
### D-162 — MF prices: AMFI's whole-market file daily, matched by ISIN, statement NAVs as a fallback, stale after 4 days
2026-10-18 · Proposed · Type: Architecture · Tasks: AOS-810 · Builds on D-50, D-79
- A daily job (23:30 India time) downloads `https://portal.amfiindia.com/spages/NAVAll.txt` (https, no redirects, 16 MB cap). The 8-column header (with Plan and Option) is checked; a change stops the import. Rows with a zero, missing or malformed NAV are skipped and counted.
- Only instruments we hold are stored (`instrument_prices`, one row per instrument, date and source), matched by ISIN first (exact plan/option), then scheme code.
- An imported statement's valuation NAV is stored as a `statement` price of its date; AMFI wins on the same date.
- Valuation uses the latest price on or before the date; older than the instrument's limit (mutual funds 4 days; listed 5, gold 35, property 200 for later sources) is labelled stale; no price at all means "valued at cost". A price is never zero.
- **Rejected:** per-scheme third-party APIs (reveal holdings, no terms); storing the whole file daily; matching by scheme code only (IDCW twins, missing codes).
