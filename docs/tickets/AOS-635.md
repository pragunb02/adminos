## Description
`CategorizeMerchantTask.read` parsed the model's reply with `Json.parseToJsonElement`, which recurses once per `[`/`{`.
A reply of `"[" × 10,000` throws `StackOverflowError`. It is an `Error`, not an `Exception`, so it passed through
`AiGateway` and failed the whole job run instead of rejecting one answer.

## Why
D-67: model output is untrusted and validated; a failed check rejects the output and falls back. A hostile or broken
model server (or a compromised Ollama host) must not be able to stop the categorisation job.

## Scope
- **In:** a shared helper for every `AiTask.read`; the gateway's handling of anything `read` throws.
- **Out:** `ReadMessageTask` (AOS-705, PR #121, not merged) already checks size and depth; it can move to the shared helper after merge.

## Acceptance criteria
- [x] `AiJson.parseObject(text, maxDepth)` refuses a reply over 16,384 characters or deeper than `maxDepth` (brackets in strings don't count) before parsing, and returns null on malformed or non-object JSON
- [x] `CategorizeMerchantTask.read` uses it (flat object, depth 1); `"[" × 10,000`, deep nesting inside a field and a 100,000-character reason are `Invalid(not_json_object)`
- [x] `AiGateway` turns any `Throwable` from `read` (including `StackOverflowError` and `OutOfMemoryError`) into `Rejected(read_failed)`, audited as rejected, with the call settled at its real cost
- [x] A `CancellationException` from `read` is re-thrown, never swallowed

## Design
- **Options considered:** 1) catch `StackOverflowError` only in the task (each task repeats it; other errors still escape);
  2) a shared pre-parse check (size + depth, one linear pass, the AOS-705 approach) used by all tasks, plus a gateway
  guard so a validator bug of any kind is a rejected answer.
- **Decision:** option 2: defence in depth. **Patterns:** shared helper (DRY) in `domain/ai`.
- **Extensibility:** a new task calls `AiJson.parseObject(text, maxDepth = n)`.
- **Impact:** domain only. New reason code `read_failed` (matches `[a-z0-9_]{1,48}`). No schema, route or contract change.

## Security
- **Exposes:** nothing new. **Threat:** a malicious or broken model server returns huge or deeply nested JSON to crash
  the parser (denial of service of the job). **Stops it:** size check, then a linear depth scan, before any recursive
  parsing; and the gateway rejects anything the validator throws. Cancellation still propagates, so shutdown and
  timeouts keep working. No content is logged; the audit row holds only the code.
- Tests: hostile unit inputs (10,000 brackets, 5,000 nested objects, oversized replies, malformed JSON, escaped quotes,
  unbalanced brackets) and gateway tests with a validator throwing `StackOverflowError`, `OutOfMemoryError`,
  `IllegalStateException` and `CancellationException`.

## Verification
- Before (main): `CategorizeMerchantTask.read("[" × 10,000)` and `AiGateway.run` both threw `java.lang.StackOverflowError`.
- After: `read` → `Invalid(not_json_object)`; `gateway.run` → `Rejected(not_json_object)`.
- `./gradlew test integrationTest koverVerify` green (1,790 unit, 144 integration); `./gradlew -q categorizationReport` unchanged (83.3% / 92.0%).

## Resolution
Shared `AiJson.parseObject` checks size and depth before parsing; `CategorizeMerchantTask` uses it; `AiGateway`
rejects (`read_failed`) anything a validator throws, except cancellation. Merge pending reviews.
