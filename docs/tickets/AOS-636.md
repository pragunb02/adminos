## Description
The repo is public (`pragunb02/adminos`), but test fixtures, unit tests, Go tests and web e2e mocks used what looks
like the owner's real personal Gmail address as the "owner" in sign-in, Gmail-connection and webhook tests, and
the owner's full name as the fake Google profile name. Other fixtures used the owner's first name in addresses,
UPI IDs and device names, and person-like addresses on real consumer mail providers or on `example.in` (a real,
registrable domain, not a reserved one). Replace all of them with clearly fake values on reserved domains and add a
guard so they can't come back.

## Why
§4a check 3 and D-33: no personal data in code or fixtures. A real address in a public repo invites phishing and
account targeting of the one account that can sign in (D-91 owner-only).

## Scope
- **In:** every test, fixture and e2e file in `services/api/src/test`, `services/workers`, `tools`, `apps/web`
  (`src/**/*.test.*`, `test/`, `e2e/`). A guard test.
- **Out:** rewriting git history (see notes); docs that name the owner as the decision-maker (`Accepted by Pragun`,
  BRD owner line): the repo's GitHub account already carries the name, and these are process records. The
  `pragunb02/adminos` repo coordinates in `scripts/` (needed). BACKLOG, DECISIONS, PROGRESS (not edited by this task;
  see notes for one line in PROGRESS).

## Acceptance criteria
- [x] The owner's personal Gmail address appears nowhere in code, tests, fixtures or e2e (was in 21 files across
      Kotlin, Go and web, 73 occurrences plus case variants). It is now `owner@example.com`, including the
      `IdentityCoverageFakes` `ownerEmail` default and `FakeGoogleServer.userInfo`.
- [x] The owner's full name (fake Google profile) is `Test Owner`; first-name values (`name`, greeting, device name,
      UPI ID, variable names) are `Owner` / `owner`.
- [x] Person-like addresses on consumer mail providers (`…@gmail.com`, `…@icloud.com`) and on unreserved
      `example.in` / `example.co.in` are on `example.com`.
- [x] Phone numbers: none real-looking. Fixtures already use obviously fake ones (`98000 000xx`, `9876543210`).
      Generic Indian names in parser fixtures (e.g. "Rohit Sharma", "Ravi") are common placeholders, kept.
- [x] Bank and Google service senders (`alerts@hdfcbank.net`, `…@system.gserviceaccount.com`) are kept: they are
      institutional, and the sender-authentication tests depend on them.
- [x] A guard test (`FixturePersonalDataTest`) fails if any test file or fixture in the API, workers, tools or web uses a
      personal mailbox provider or an unreserved "example" domain; its message names only the file, line and domain.
- [x] All suites still pass.

## Design
- **Context:** fixtures were written with real-looking data early on (AOS-1xx/4xx); nothing stopped it.
- **Options considered:** 1) replace by hand only; 2) replace and add a guard test over every test tree;
  3) a pre-commit hook. A hook isn't enforced for agents or fresh clones, and there is no CI yet (AOS-622).
- **Decision:** 2. The guard runs inside `./gradlew test`, which every API change runs. It denylists personal
  mailbox providers and unreserved "example" domains rather than allowlisting every bank sender.
- **Impact:** test code only; no production code or schema change.

## Security (D-100 §4a)
- **Exposes:** nothing new. Removes personal data from the public tree.
- **Abuse and what stops it:** someone reading the repo learns the one account that can sign in → address removed
  from the tree; the guard stops a new fixture reintroducing a real mailbox address. History still has it (below);
  the sign-in itself stays owner-pinned, verified and passkey-protected (AOS-614, AOS-617), so knowing the address
  doesn't let anyone in.
- **Tests:** the guard's own unit check (refuses `gmail.com`, `icloud.com`, `example.in`, `example.co.in`; allows
  `example.com`, `*.example.org`, `*.example`, bank domains), plus the repo scan. Every changed test still passes.
  No route, input or screen changes, so no new route or Playwright attack spec applies.

## Risks / notes
- **Git history still contains the old values.** 9 commits (from 2026-10-16) added or changed lines with the personal
  address, and older commits have the full name in fixtures. Removing them needs a history rewrite
  (`git filter-repo` with a replacement list), a force-push to `main` (branch protection forbids it today, so it must
  be lifted briefly), and every clone and open PR branch rebased. That's the owner's decision: the address is
  already exposed to anyone who cloned or forked, so a rewrite reduces but doesn't remove exposure.
- **`docs/PROGRESS.md` line 147** (an AOS-405 entry) still contains the personal address. This task doesn't edit
  PROGRESS; the integrator should replace it with `owner@example.com` when they next update that file.
- The owner's first name in docs (decision attributions, BRD owner line, the `pragunb02` account) is left as is.
