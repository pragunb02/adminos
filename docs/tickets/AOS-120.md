## Description
- Date-only `from`/`to` query params are whole days in `Asia/Kolkata` (`QueryParams.DEFAULT_ZONE`).
- Use the user's stored `timezone` instead. Needed for public users outside India, and for "today" in the daily view.

## Acceptance criteria
- [x] Day boundaries follow `users.timezone`; tested with a non-IST user (New York: the windows pick different rows)
- [x] An unknown stored timezone is dropped from the token (logged) and the default zone is used

## Resolution
Done.
- The access token carries a `tz` claim (the user's timezone, validated).
- `UserPrincipal.zone` and `ApplicationCall.userZone`; `rangeStartParam`/`rangeEndParam` use it.
- Tokens from before this change have no `tz`, so they use Asia/Kolkata until they expire (≤1h).
- A timezone change applies on the next token refresh.
- **Tests:** `FinancialRoutesContractTest` (New York user), `JwtServiceTest` (claim round-trip, unknown zone dropped). Unit 304/304, integration 50/50.
- Actual 1h vs ETA 1h.
