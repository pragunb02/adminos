## Problem
- Money moved between your own accounts showed up as both spending and income.
- Paying your credit-card bill counted card purchases twice.

## Design (approved by Pragun, D-39)
- **`nature`** on every transaction (`spend`, `income`, `transfer`, `refund`, `reversal`), and **totals add up by nature**.
- `transaction_links.relation` (`duplicate`, `transfer`, `refund`, `reversal`) sits beside the state (merged, suggested, rejected).
- **Card bill payments auto-marked as transfers** (Pragun agreed).

## Rules (`TransferDetector`)
- **Card bill:** a debit, not itself a card purchase, matching high-precision patterns: `CREDIT CARD`, `CC PAYMENT`, `CARD BILL`, BillDesk + card, `CRED` (whole word), `cred.club`, autopay + card. `SALARY CREDITED` and `INCRED` don't match.
- **Pair:** a debit and a credit of the exact amount on **two different, known accounts** of the user.
  - **Score:** amount +4; timing +3 (≤10 min real-time), +1 (≤1 h), +2 same day / +1 next day (statements); transfer narration +3; names the other account's last 4 +5.
  - **Bands:** ≥8 auto, 6–7 suggest, ambiguity margin 3.
- Runs **after categorisation** and sets category Transfer, but a category the user chose is kept.

## Implementation
- **V14:** `transaction_nature` enum + `transactions.nature` (backfilled from type, NOT NULL, indexed); `transaction_links.relation`.
- **`TransactionNature`** with defaults by type; mapped in the Exposed repository.
- **Generic `Relation` side effects** in the pipeline: a step can update an existing transaction and add a link in the writer's single unit of work (reused by AOS-209).
- **`TransferStep`** after `CategorizeStep`.
- **Totals now use `nature = spend`:** weekly spend, spending by category and category averages (unusual-charge baseline), in both the Exposed and in-memory implementations.
- **Review API generalised:** `/api/v1/transactions/suggestions?relation=…` with `/{id}/confirm|reject`. Confirm acts per relation (duplicate → merge, transfer → both sides become transfers). It replaces `/duplicates`, which had no client.
