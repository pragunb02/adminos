## Description
- Make one categorizer, used by every source.
- When Pragun corrects a category, remember it for that merchant: future transactions use it, and past ones are re-labelled.

## Why
- D-20 is "my category corrections remembered".
- Today a correction changes only one row.
- Two rules hide real spending as "Transfer": any unknown UPI payee, and anything with NEFT/IMPS/RTGS in the narration.

## Scope
- **In:**
  - remembered rules (V15 `category_rules`);
  - rule order: user rule → known merchant → pattern → Other;
  - PATCH learns, with `remember` (default true);
  - backfill of past transactions;
  - removing the wrong rules and dead code (the unused `CategorizationStrategy`/`CategoryResult` and the no-op AI queue).
- **Out:**
  - the Go categorizer, which stays until AOS-401 retires the Go Gmail path;
  - an AI fallback (later);
  - a rules management UI (AOS-3xx).

## Acceptance criteria
- [x] A correction creates or updates one rule per UPI ID, or per merchant name when there's no UPI ID.
- [x] New transactions from that payee get the remembered category (`categorySource = "rule"`).
- [x] Past spending and refunds from that payee are re-labelled, except ones the user set by hand.
- [x] `remember: false` changes only the one transaction.
- [x] An unknown UPI payee is Other, not Transfer; NEFT/IMPS alone don't mean Transfer.
- [x] Own-account transfers are still detected (AOS-208 step runs after).

## Design (approved by Pragun 2026-10-16)
- **Decision:** a Chain of Responsibility inside `CategorizationService`.
  - User rules come first (repository lookup: UPI ID, then merchant).
  - Then the built-in merchant list, then the patterns.
- **Extensibility:** the AI fallback later becomes one more link before Other.
- **Impact:**
  - V15 table;
  - `CategoryRuleRepository` (Exposed + in-memory);
  - `CategorizeStep` passes the whole transaction;
  - PATCH body adds `remember`;
  - the learn step and backfill run in one unit of work.
