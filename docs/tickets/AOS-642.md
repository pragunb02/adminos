## Description
`npm run test:coverage` failed at random on a loaded machine (load average about 86): `findBy*` gave up after Testing Library's default 1 s on pages that render correctly. Seen in `briefings/page.test.tsx`, `documents/page.test.tsx`, `transactions/leaks.test.tsx` and `anomalies/[id]/page.test.tsx`; each passed on rerun. A flaky required `web` check would stall the merge train.

## Acceptance criteria
- [x] The async-util timeout is 5 s for every web test, set once in `test/setup.ts` with the reason.
- [x] The per-test timeout (15 s) is above it, so a slow `findBy` fails as itself.
- [x] No test lowers it again: the three `{ timeout: 2000 }` overrides in the settings test are gone; `vi.waitFor` in the documents test uses 5 s.
- [x] Other global causes checked: every fake-timer test restores real timers in `afterEach`; the setup now also restores them after every test, so one forgotten restore can't stall later tests.
- [x] `npm ci && npm run typecheck && npm run lint && npm run test:coverage && npx next build` green.

## Security
Test configuration only; nothing shipped changes.

## Activity log
- 2026-10-18 — Claude (integration engineer): seen while integrating #124 and #130; fixed on its own branch.

## Resolution
`apps/web/test/setup.ts` (`configure({ asyncUtilTimeout: 5_000 })`, real timers after each test), `apps/web/vitest.config.mts` (`testTimeout: 15_000`), and the two tests that set shorter timeouts. Web gates green (482 tests, 99.02% lines).
